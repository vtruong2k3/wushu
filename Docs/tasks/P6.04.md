## 1. Analysis

### 1.1 Goal

From an alignment, two curves on **the reference's own timeline** (W8: tempo is always reported on the original time
axes, DTW only compares shape):

1. **The local tempo ratio** `ρ(k) = d t_query / d t_ref` along the path (Appendix C.4): above 1 the query takes longer
   than the reference at that moment, below 1 it is faster; smoothed over a window of `smooth_s` seconds of the reference
   clock.
2. **The deviation of each unit** (a joint's position, a segment's angle) on the reference timeline: how far the matched
   query frame is from the reference frame, unit by unit, so a coach can see which joint differs and when.

### 1.2 Facts read (2026-11-17)

- Plan row P6.04: "local speed along the path against real time; deviation curve per joint on the reference timeline",
  output `compare/tempo_ratio.py`, test T-CMP-06 ("SYN-10: local speed ratio about `k(t)`"); tolerance: median
  `|ρ/k − 1| ≤ 10 %` after a smoothing of 0.5 s.
- Appendix C.4: `ρ(k) = d t_query / d t_ref` along the path, smoothed with a 0.5 s window; the deviation of each joint on
  the reference timeline.
- AGENTS.md §5.2: real timestamps, never a constant fps: the times are `FrameFeatures.t_sec` (the grid of the final layer),
  not row indices.
- SYN-10 gives `rate_k` at every query row and `t_ref_of_query` (the truth of the warp).

### 1.3 Scope

**In:** `compare/tempo_ratio.py`: `TempoCurve`, `local_tempo(alignment, *, smooth_s)`, `DeviationCurve`,
`deviation_curve(alignment)`; tests T-CMP-06 (golden) and T-CMP-06b..h; mutation check; docs. **Out:** a judgement of the
tempo (a threshold is a record's, later), the band (P6.06), the display (P8).

### 1.4 Design

- **Matched query time** on the reference timeline: `τ(k)` = `Alignment.matched_query_times()` of P6.03b (the mean of
  `t_query(i)` over the path cells `(i, k)`; a full path touches every reference row, so `τ` is defined on every row of an
  `ok` result). It is not written again here (overview §3.4).
- **Local ratio:** `ρ(k)` = the least-squares slope of `τ` against `t_ref` over the reference rows whose time is within
  `smooth_s / 2` of `t_ref(k)` (a real-clock window, so an uneven grid is handled); NaN with a reason when the window holds
  fewer than two rows or no spread of time. `smooth_s` is required (no default; Appendix C suggests 0.5 s; overview §3.5).
- **Whole-segment ratio:** `(t_q,end − t_q,start) / (t_r,end − t_r,start)` as a summary.
- **Deviation:** for each reference row `k` and unit `u`, the mean over the path cells `(i, k)` of `‖q_u(i) − r_u(k)‖`
  over the cells where the unit is valid in both frames (NaN where it is never), and the cost of the cell as the total.
  Positions are in trunk lengths, angles the chord of P6.02 (0 to 2); a unit of weight 0 in the alignment is still reported
  (it is a deviation, not a cost).
- **No path:** both functions return curves of NaN with the reason `no_path` (never zeros).

### 2.6 Interface fixed at the re-read (2026-11-18; the plan of §1.4 left the fields open, none of it changes a contract of `P6_overview.md`)

```python
class TempoReason(enum.IntEnum):      # why a ratio is NaN: valid 0, window_too_small 1, no_path 2
class DeviationReason(enum.IntEnum):  # valid 0, not_valid_in_both 1, no_path 2, no_cell 3

@dataclass(frozen=True, eq=False)
class TempoCurve:      # every array is new and read-only; one entry per REFERENCE row k
    t_ref (m,) float64 s        # the reference's real clock (FrameFeatures.t_sec)
    t_query (m,) float64 s      # matched query time tau(k) (Alignment.matched_query_times()); NaN without a cell
    ratio (m,) float64          # rho(k), query seconds per reference second (above 1: the query is slower); NaN + reason
    reason (m,) uint8           # TempoReason
    window_rows (m,) int64      # rows of the window with an observed tau (the evidence behind a ratio)
    smooth_s float              # echoed, no default
    whole_ratio float           # (t_q,end - t_q,start) / (t_r,end - t_r,start) of the two segments; NaN + whole_reason
    whole_reason int            # TempoReason
    status "ok" | "no_path"; reference_recording_id; query_recording_id; settings (the alignment's, read-only)

@dataclass(frozen=True, eq=False)
class DeviationCurve:  # one entry per reference row k (and unit u)
    t_ref (m,), t_query (m,)    # as above
    values (m, U) float64       # mean over the path cells (i, k) with the unit valid in both of |q_u(i) - r_u(k)|
                                #   (trunk lengths for a position, the chord 0..2 for an angle); NaN + reason otherwise
    reason (m, U) uint8         # DeviationReason
    n_valid (m, U) int64        # path cells on the row that the mean is made of
    cells (m,) int64            # path cells on the row
    total (m,) float64          # mean over the path cells on the row of the alignment's cost c(i, k) (NaN: no cell)
    units (U names), kinds (U "position"/"angle"), status, reference_recording_id, query_recording_id, settings

local_tempo(alignment, *, smooth_s) -> TempoCurve;  deviation_curve(alignment) -> DeviationCurve
```

Rules written down now: (1) the window of row `k` is every reference row `j` with `|t_ref(j) - t_ref(k)| <= smooth_s / 2`
(plus 1e-9 s, so a row exactly on the edge is in it whatever the rounding of the clock, as `dtw`'s band does for
fractions); the fit uses only the rows of the window whose `tau` is observed (a row with no path cell is NaN and is left
out, never filled); fewer than two such rows, or a squared spread of time that is not above 0, is NaN with
`window_too_small`. (2) The slope is the ordinary least-squares slope `sum(dt dq) / sum(dt^2)` of `tau` against `t_ref`
with both centred on the window's own mean. (3) `whole_ratio` is read from the two segments' clocks (not from `tau`, whose
first and last rows are means), needs both segments to have two rows, and is NaN with `no_path` when there is no path
(nothing is reported for an alignment that was not made). (4) Both functions refuse (`CompareError`) an argument that is
not an `Alignment`, and an `Alignment` whose clocks are not clocks or whose arrays do not fit each other: `align`
guarantees this, a hand-made `Alignment` does not (AGENTS.md 5.2). (5) A unit of weight 0 is reported (Q3). (6) `smooth_s`
is a finite number above 0, a Python or numpy number (not a bool), echoed as a Python float.
