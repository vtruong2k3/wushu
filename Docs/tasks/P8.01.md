## 1. Analysis

**Goal:** a FastAPI application that becomes the single local server: JSON API under `/api`, static serving of the
React build (`web/dist`) with SPA fallback, uniform error format, health endpoint; Streamlit removed.

**In scope:** `api/` package, settings additions, `/api/health`, error handlers, static/SPA serving, entry point
`python -m taiji_ai.api` (127.0.0.1 only), contract tests T-API-01..04, removal of Streamlit (`app/`, dependency),
docs/notice/tool updates that mention Streamlit.
**Out of scope:** any domain endpoints (P8.03+), auth, CORS (same origin by design), web code (P8.02).

**Inputs / interfaces:**
- `taiji_ai.config.Settings` (frozen dataclass; env overrides `TAIJI_DATA_DIR`, `TAIJI_MODELS_DIR`, `TAIJI_DEVICE`).
- `taiji_ai.pose.registry.ModelRegistry` — verifying SHA-256 of ~157 MB takes noticeable time → do it **once at
  startup**, cache the result; health returns the cached status (no hashing per request).
- `taiji_ai.store.db.connect()` applies migrations → run once at startup; health opens a short-lived connection to
  read `schema_migrations`.

**Existing code read:** `config.py`, `store/db.py`, `pose/registry.py`, `app/Home.py` (Streamlit: shows model registry +
migrations — the health endpoint replaces it), `pyproject.toml`, `tools/env_check.py`, `README.md`,
`THIRD_PARTY_NOTICES.md`, AGENTS.md §5.7/§7.

**Versions (PyPI, 2026-11-14):** fastapi 0.162.6 (MIT; needs starlette ≥ 0.46, pydantic ≥ 2.9), uvicorn 0.54.0
(BSD-3), httpx 0.28.1 (BSD-3, needed by `fastapi.testclient`). starlette 1.10 / uvicorn 0.54 are currently present
only because Streamlit pulls them; after the change FastAPI pulls starlette and we depend on uvicorn directly.

**Constraints:** AGENTS §5.7 (no heavy work in API process; bind 127.0.0.1), §5.6 (models only from verified registry),
errors must not leak stack traces or internal paths (T-API-02), §9 (record new deps in THIRD_PARTY_NOTICES).

**Risks:** SPA fallback swallowing `/api/*` 404s (→ explicit check, T-API-03); hashing models on every health call
(→ startup cache); tests touching the real `data/` dir (→ tests use tmp Settings).

## 6. Self-review

- Re-read: `config.py`, all `api/*.py`, `tests/api/test_api_core.py`, `tests/unit/test_config.py`, pyproject diff.
- Findings and fixes: (1) SPA route return-type union made FastAPI fail to build a response model → `response_model=None`
  (caught by the first test run); (2) a confusing no-op route reordering line in a test → replaced by `_add_api_route`
  helper; (3) `index.html` needed `Cache-Control: no-cache` so a rebuilt UI is not served stale; (4) traversal test
  extended with an absolute-path case; (5) over-long, convoluted assertion split into three.
- Edge cases covered: missing/tampered registry, no web build, unknown API path vs client route, traversal, method
  not allowed, validation without echo. Not covered (out of scope): auth, CORS (same origin by design).
- No personal data; no heavy work in the API process; models verified only at startup.
