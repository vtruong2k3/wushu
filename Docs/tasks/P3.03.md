## 1. Analysis

**Goal:** persist the raw pose of a segment so that it can be read back **identical** and so that a file that is damaged, from another version or for another skeleton is **refused**, never half read. `pose_raw.npz` is the input of the target
choice and tracking (P3.04 to P3.06) and, through them, of everything after; W4 and the cache rule (TECH_WORKFLOW 4.3) say that a valid `pose_raw.npz` lets a re-run skip pose.

**What the plan, workflow and code say (read 2026-11-16):**

- Plan row P3.03 and T-POSE-08: "`pose_raw.npz` has the right schema; save and read back give the same"; contents: every detected person (bbox, keypoints, scores, `t_sec`, `frame_index`). W4: ragged or padded with `n_persons`; P3.02 already chose compressed rows.
- Layout (TECH_WORKFLOW 4.1): `data/runs/<run_id>/pose_raw.npz`, next to `run_manifest.json`. The run folder, the `run_id` (cache key 4.3) and the run manifest belong to **P7**; this task writes and reads **a path it is given**.
- Atomic writes (4.4, AGENTS.md 5.8): `store/artifacts.atomic_save_npz` exists (temp file in the same folder, `os.replace`; refuses object arrays and the reserved names `file`, `allow_pickle`; keeps NaN). The manifest of the run is written last (P7).
- Repository conventions: Pydantic v2 models with a `schema_version` `Literal` in every persisted manifest (`schemas/_base.py`: `Manifest`, `ManifestError`, `parse_manifest`, `Seconds`, `NonNeg`, `UUID4_RE`, `SHA256_RE`); floats are never NaN or infinite in a manifest; no file names or paths in artifacts (AGENTS.md 5.9, 6).
- `PoseRaw` (P3.02) has: `recording_id`, `frame_index` (F,) int32, `t_sec` (F,) float64, `person_offsets` (F + 1,) int64, `bboxes` (D, 4) f32, `keypoints` (D, 26, 2) f32, `scores` (D, 26) f32, `from_detector` (D,) bool, `image_size`, `display_rotation`, `segment_s`,
  `params` (`PoseRunParams`), `model_fingerprint` (name -> sha256), `providers`, `stats` (`PoseRunStats`, wall clock included), and `equals()` that ignores `stats`.
- A `.npz` holds arrays only; scalars and dictionaries need a header. Pickle is not allowed (`np.load(allow_pickle=False)`).

**In scope:** `schemas/pose.py`: `PoseRawMeta` (the header, `pose_raw/1`); `pose/raw_io.py`: `save_pose_raw(path, raw) -> str` (returns the SHA-256 of the written file for the run manifest), `load_pose_raw(path) -> PoseRaw`, `PoseRawError`; tests; README, plan test rows, tracking.
**Out of scope:** where the file lives and how it is named (P7: `runs/<run_id>/`), the run manifest and its checksum field (P7), the cache decision (P7), the target choice and `track.parquet` (P3.04 to P3.06), converting to the metric inputs (P4).

**The file format (`pose_raw/1`):** arrays, all with fixed names and dtypes, and one array `meta_json` (0-d unicode string, UTF-8 JSON of `PoseRawMeta`):

| Array | Shape / dtype | Content |
| ----- | ------------- | ------- |
| `frame_index` | (F,) int32 | row of each frame in `pts.parquet` |
| `t_sec` | (F,) float64 | seconds from the stream start, strictly increasing |
| `person_offsets` | (F + 1,) int64 | persons of frame `i`: rows `[i]:[i + 1]`; starts at 0, non-decreasing, ends at D |
| `bboxes` | (D, 4) float32 | xyxy [px] |
| `keypoints` | (D, 26, 2) float32 | x y [px], upright image, y down, as the model returned them |
| `scores` | (D, 26) float32 | the model's scores |
| `from_detector` | (D,) bool | box from the detector |
| `meta_json` | () str | `PoseRawMeta` |

**Changes after the confirmation:** the file has 9 arrays (the 7 above, `schema_version`, `meta_json`); the header carries `counts` (`n_frames`, `n_detector_calls`, `n_pose_calls`, `n_persons_total`) instead of `stats`; `PoseRaw.equals` must treat NaN as equal to NaN
(`np.array_equal(..., equal_nan=True)`) or a pose with a NaN score would never equal itself; `atomic_write_bytes` leaves its `.tmp` behind when the write or `os.replace` fails (found while planning the atomic test: BUG-0069, fixed here).

`PoseRawMeta` (`extra = forbid`): `schema_version: Literal["pose_raw/1"]`, `skeleton: Literal["halpe26/1"]` (checked against `pose.skeleton.SKELETON_ID` too), `recording_id` (UUID4), `image_size` (width, height > 0), `display_rotation` in {0, 90, 180, 270},
`segment_s` (start < end, finite), `params` (the five `PoseRunParams` fields), `model_fingerprint` (name -> sha256, at least one), `providers` (name -> provider, at least one), `stats` (`n_frames`, `n_detector_calls`, `n_pose_calls`, `n_persons_total`, `elapsed_s`),
`n_frames`, `n_persons_total` (checked against the arrays). Units and coordinates are in the docstrings.

**Load rules (strict):** exactly the arrays above (a missing or an extra array is an error); the dtype and the shape of each; `D` equal to the last offset; offsets start at 0 and never decrease; `t_sec` strictly increasing; `frame_index` strictly increasing and non-negative;
`n_frames` and `n_persons_total` of the header equal to the arrays; the schema version and the skeleton equal to the ones this code knows (another version is refused with a message that names both); no pickle; a file that cannot be read as an `.npz` (truncated, wrong format)
is a `PoseRawError` with the cause chained. Keypoints and scores are **not** validated for range or NaN (raw layer: what the model returned); the header must be finite.

**Constraints that apply:** AGENTS.md 5.1 (no filling, no clamping, NaN kept as it is), 5.3 (raw layer separate), 5.8 (atomic write), 5.9 and 6 (no paths or file names in the file; log IDs only), schemas rule (version in every persisted file), 9.4 point 7 (no dataset content in the repository).

**Unknowns, risks:**

1. *A `.npz` is a zip and its bytes are not deterministic (timestamps in the zip headers)*: two saves of the same `PoseRaw` can differ in SHA-256. Equality is defined on the **content** (`PoseRaw.equals`); the run manifest (P7) records the SHA-256 of the file that was written. Stated here so nobody compares file hashes of two saves.
2. *Header as one JSON string array vs separate scalar arrays*: JSON keeps one validated model and room to add fields with a version bump; the cost is that a reader needs the model. Chosen: JSON.
3. *Size*: a 6 minute clip at 30 fps and one person is about 10 800 rows: about 2.3 MB before compression; the compressed file is smaller. Persons per frame multiply it. No problem expected; measured in the task.
4. *`stats.elapsed_s` is a wall clock*: stored for information, never part of equality, and a header rule keeps it finite and non-negative.
5. *Forward compatibility*: strict loading means a later version (`pose_raw/2`) needs a reader for both; the version in the file and the error message make that explicit.

**Questions for the maintainer (the plan proceeds with the default if there is no answer):**

| # | Question | Default |
| - | -------- | ------- |
| Q1 | Header form | one `meta_json` array validated by `PoseRawMeta` (not many scalar arrays) **plus a separate 0-d array `schema_version`** so that any reader can check the version before parsing the JSON (confirmed with this addition) |
| Q2 | Store `stats` (including wall clock) in the file | **changed (confirmed): the file stores the deterministic counts only** (`n_frames`, `n_detector_calls`, `n_pose_calls`, `n_persons_total`); the wall clock `elapsed_s` belongs to the run manifest (`runtime`, TECH_WORKFLOW 4.2) and `PoseRunStats.elapsed_s` becomes `float | None` (`None` after a load: no invented 0) |
| Q3 | Where the file is written and its name | decided by the caller (P7: `runs/<run_id>/pose_raw.npz`); this task takes a path, **does not create the folder** (a missing folder is a `PoseRawError`) |
| Q4 | Load strictness | strict (any missing or extra array, wrong dtype or shape, inconsistent counts or another version is an error) **with a reader table by version** (`{"pose_raw/1": _read_v1}`): a later version adds a reader, never a silent upgrade (confirmed) |
| Q5 | Compression | compressed (`atomic_save_npz` as it is) |
| Q6 | `save_pose_raw` returns the SHA-256 of the written file | yes (the run manifest will record it) |
| Q7 | Version name | `pose_raw/1` |

## 2. Plan

**Design:** `save_pose_raw(path, raw)`: build `PoseRawMeta` from `raw` (this validates the header), check the arrays of `raw` against the same rules as the loader (so a bad `PoseRaw` cannot be written), `atomic_save_npz(path, **arrays, meta_json=np.array(json))`, return
`sha256_file(path)`. `load_pose_raw(path)`: `np.load(path, allow_pickle=False)` in a `with`, read the header first and validate it, then the arrays (names, dtypes, shapes, consistency), then rebuild `PoseRaw` (`params` as `PoseRunParams`, `stats` as `PoseRunStats`); any failure is a `PoseRawError`.
One shared function `_check_arrays(...)` applies the rules in both directions.
