## 1. Analysis

**Goal:** bring one phone video into the system so that it can never be changed or lost, its real timestamps are stored,
and it is linked to a pseudonym with valid consent. W1 steps 1–4 and 6 (the proxy, step 5, is P2.03).

**Facts read (2026-11-15):**

- `store/artifacts.py`: `sha256_file`, `atomic_write_bytes/text/json`, `atomic_save_npz` (tmp + fsync + `os.replace`); no
  parquet helper. `store/db.py`: `connect()` applies numbered migrations; `PRAGMA foreign_keys = ON`.
- `io/probe.py` `probe_video()` (ffprobe CLI, raises `ProbeError`); `io/frames.py` `scan_pts()` returns sorted `t_sec` and the
  time base as a float, **not** the integer PTS that `pts.parquet` needs; `is_vfr()` is wrong for coarse time bases
  (**BUG-0046**, measured while planning: CFR 30 fps at time base 1/1000 → `True`).
- `recording.participant_id` is a foreign key to `participant`; `participant.consent_analysis` may be 0 in the database
  although analysis is the condition to take part (P1.06 finding).
- Config: `Settings.data_dir` (`TAIJI_DATA_DIR`), `db_path`, `migrations_dir`. No CLI entry point exists in `pyproject.toml`.
- AGENTS.md §6 and TECH_WORKFLOW §10.1: log IDs only, never the user's file name or source path; §10.2: user videos are
  processed by FFmpeg/PyAV in a worker with **limits on duration and size**; §5.7: no heavy work in the API process.
- Planning experiment (scratchpad, synthetic clips): for an AAC/MP4 made by ffmpeg, audio and video both start at 0 and a
  click at 1.000 s lands at 1000.06 ms in the 16 kHz WAV, so the audio start offset can be read from ffprobe; phone files are
  checked in P2.07.

**In scope:**

1. `io/frames.py`: `scan_pts_ticks(path) -> PtsScan` (integer PTS in presentation order, `time_base` as a `Fraction`,
   `start_pts`); `scan_pts` keeps its signature and uses it. `is_vfr` fixed on ticks (BUG-0046).
2. `store/artifacts.py`: `atomic_write_parquet(path, table)`.
3. `store/recordings.py`: `find_by_sha(conn, sha)`, `get_participant_consent(conn, participant_id)`, `insert_recording(conn, row)`.
4. `io/ingest.py`: `ingest_recording(path, meta, settings) -> IngestResult(manifest, created: bool)` and the errors
   `IngestError` → `SourceUnreadable`, `NoVideoStream`, `ConsentMissing`, `MetaInvalid`, `SourceTooLarge`.
5. CLI `taiji ingest <file> --participant P03 --session S01 --take S01-P03-T02 --camera camA [--capture …]`
   (`taiji_ai/cli.py`, `[project.scripts] taiji = "taiji_ai.cli:main"`); prints the `recording_id`, never the path.

**Out of scope:** proxy (P2.03), audio extraction (P2.04), batch ingest of a whole session (P9.03), the upload page and API (P8),
participant registration (P2.08).

**Design — order of operations (nothing half-done can be left behind, T-IO-08):**

1. Validate `meta` (P2.01 rules) and the source: exists, is a file, size > 0 and ≤ the size limit (Q2).
2. Hash the source (streaming). If the SHA is already in `recording` → return the existing manifest, `created = False`
   (T-IO-07: idempotent, no second row, no second copy).
3. Check the participant: row exists, `consent_ref` not empty, `consent_analysis = 1`; else `ConsentMissing` (AGENTS.md §9.5).
4. Probe and scan **the source in place**: no video stream, unreadable or zero frames → error before anything is written;
   duration ≤ the duration limit (Q2).
5. Create `data/recordings/.staging-<uuid>/`; copy the source to `source.<ext>`; hash the copy; if it differs → error and
   remove the staging folder; set the copy read-only.
6. Write `pts.parquet` (`frame_index` int32, `pts` int64, `t_sec` float64; schema metadata `time_base`, `start_pts`) atomically.
7. Build `RecordingManifest`; write `recording.json` **last** in the staging folder.
8. Rename the staging folder to `data/recordings/<uuid>/` (same volume, one `os.replace`).
9. Insert the `recording` row in one transaction. If it fails (for example a second process inserted the same SHA in
   between), move the folder to `data/recordings/.orphan-<uuid>/` and raise; a recording folder without a row is the only
   possible leftover and is reported by a check, never a row without its folder.
10. Hash the source again; it must equal step 2 (T-IO-06: the original is not changed).

**VFR rule (BUG-0046 fix):** on integer ticks, an interval deviates when `|dt − median| > max(1 tick, rel_tol × median)`
(`rel_tol = 0.01` as in W1); `vfr = True` when deviating intervals exceed a small share of all intervals (the share is fixed
from the fixtures and stored with a rule version in the manifest). Duplicate PTS are counted (`n_duplicate_pts`), never dropped.
