## 1. Analysis

### 1.1 Goal

Before two segments are compared, say whether they may be (W8: "only when both segments have the same `action`, `side`,
`variant` and `view_category`, and the coverage of both is at least a threshold"), and when not, every reason why, so that
the coach sees why no comparison is shown. A refusal is a result, not an error.

### 1.2 Facts read (2026-11-17)

- Plan row P6.05: "rejection rules: another action, side or view, low coverage", output `compare/guards.py`, test T-CMP-07
  ("another action, side or view, or a low coverage, is refused, with a reason"); acceptance of P6: "another action is
  refused".
- Ontology (`config/ontology_v0.yaml`, `schemas/ontology.py`, P1.04, DEC-0022): actions `A01..A24` with `technique` (shared
  by the numbers that are the same technique), `sides` (left, right, none) and `repetitions` (a segment's `occurrence`);
  vocabularies `sides`, `view_categories` (front, side, oblique, back, unknown), `flags` (orientation_change, occlusion,
  perspective_shift); the form `taiji24`, `ontology_version` v0, `status` draft_unconfirmed.
- The `segment` table (migration 0001) holds `action`, `side`, `occurrence`, `view_category`, `flags` (JSON),
  `reference_of`; segments are written by P8.06 (not built), so the guard reads a plain description, not the database.
- The metrics block on flags per metric (trunk lean on `orientation_change`, speeds on `perspective_shift`, P5.05, P5.06).
- No universal threshold (AGENTS.md 5.5): the coverage minimum is an argument.

### 1.3 Scope

**In:** `compare/guards.py`: `SegmentInfo`, `GuardDecision`, `check_comparable(...)`; tests T-CMP-07a..h; mutation check;
docs. **Out:** reading segments from the database (P8.06 and P7 build `SegmentInfo`), mirroring a left movement onto a
right one (explicit, later), the comparison itself (P6.03b).

### 1.4 Interface

```python
@dataclass(frozen=True)
class SegmentInfo:
    action: str              # ontology id, A01..A24
    side: str                # left, right or none: one of the action's sides
    variant: str             # the form and the ontology version, e.g. "taiji24/v0"
    view_category: str       # front, side, oblique, back, unknown
    flags: frozenset[str]    # ontology flags set on the segment

@dataclass(frozen=True)
class GuardDecision:
    comparable: bool
    reasons: tuple[str, ...]   # every reason, in a fixed order; empty when comparable
    coverage_reference: float | None; coverage_query: float | None
    min_visible: int; min_coverage: float

def check_comparable(reference: SegmentInfo, query: SegmentInfo,
                     reference_features: FrameFeatures, query_features: FrameFeatures, *,
                     min_visible: int, min_coverage: float, ontology: Ontology | None = None) -> GuardDecision
```

**Reasons** (a closed list, in this order): `action_differs`, `side_differs`, `variant_differs`, `view_differs`,
`view_unknown` (a segment whose view is unknown is never compared), `flagged_reference:<flag>`, `flagged_query:<flag>` (for
the blocking flags, Q3), `no_rows_reference`, `no_rows_query`, `coverage_low_reference`, `coverage_low_query`.

**Coverage** of a segment = the share of its rows where at least `min_visible` units of the features are valid (the rows
the cost can use); `None` for a segment without rows.

### 1.5 Questions for the maintainer

| #  | Question | Default if no answer |
| -- | -------- | -------------------- |
| Q1 | Same `action` number, or same `technique` (a technique that occurs under two numbers)? | **The same action number**: a technique in another place of the form can start from another stance; comparing across numbers is a coach's choice, later |
| Q2 | All reasons or the first one | **All of them**, in a fixed order: the coach sees everything that is wrong at once |
| Q3 | Which flags block | **`orientation_change` and `perspective_shift`** (the shape in the image plane is not the same movement); **not `occlusion`** (the masks of the features already leave the hidden joints out) |
| Q4 | The coverage minimum | **Required** (`min_coverage` in `(0, 1]`, no default); the pipeline's configuration passes it |
| Q5 | A view `unknown` | **Never comparable** (`view_unknown`), even with another `unknown` |
| Q6 | Check the values against the ontology | **Yes**: an unknown action, a side the action does not have, an unknown view or flag is a `CompareError` (a wrong description is a programming error, not a refusal) |
