## 1. Analysis

### 1.1 Goal

`dtw(cost, *, band, step) -> DtwResult`: the warping path of minimum cost through a cost matrix, inside a Sakoe-Chiba band
and with a step pattern whose slope is limited, and the shape distance `D = Σ c(path) / len(path)` of Appendix C.4.

### 1.2 Facts read (2026-11-17)

- Plan row P6.03: "DTW with a Sakoe-Chiba band and a step pattern that limits the slope; returns the path and a normalised
  distance", tests T-CMP-03 ("identical sequences: distance 0, diagonal path"), T-CMP-04 (golden SYN-10: shape about 0 when
  stretched, the path respects the band), T-CMP-05 ("check against `dtaidistance` on data without a mask, same band").
- Appendix C.3: band `|i/n − k/m| ≤ r` (suggested `r` 0.1 to 0.2); symmetric step pattern with a slope limit (for example
  `P = 1`), "no more than two horizontal or vertical steps in a row"; optional open-begin and open-end. C.4: `D = Σ c(path) /
  len(path)`. C.6: NumPy, Numba only beyond 2,000 frames; check against `dtaidistance` (Apache-2.0) without a mask.
- `dtaidistance` and Numba are not in `uv.lock`. `dtaidistance.dtw` takes two series, not a cost matrix, and its `window`
  is an absolute band `|i − k| ≤ w` with unit steps.
- Segments are 150 to 900 rows at 30 fps; a band of 0.2 leaves about 40 % of the cells.

### 1.3 Scope

**In:** `compare/dtw.py`: `DtwResult`, `band_mask(n, m, band)`, `dtw(cost, *, band, step)`; the two step patterns of §1.4;
tests T-CMP-03, T-CMP-05 (on an independent implementation, Q3) and T-CMP-03b..h; mutation check; docs. **Out:** features
and cost (P6.01, P6.02), the alignment of two segments and the golden tests SYN-10 and SYN-11 (P6.03b), open-begin and
open-end (Q4), Numba.

### 1.4 Design

- **Band:** a cell `(i, k)` is allowed when `|i/(n−1) − k/(m−1)| ≤ r + 1e-12` (a row index of a one-row matrix counts as
  0); `r` in `(0, 1]` is required (no default, overview §3.5); `r = 1` is no band. Appendix C writes `|i/n − k/m|`;
  with `n − 1` and `m − 1` the two corners `(0, 0)` and `(n−1, m−1)` are on the diagonal, so a band never excludes the
  start or the end of a path (the docs say so).
- **`symmetric1`** (unit steps, the classical pattern of `dtaidistance`): `g(i,k) = c(i,k) + min(g(i−1,k−1), g(i−1,k),
  g(i,k−1))`, `g(0,0) = c(0,0)`. Used to check the implementation against an independent one; no slope limit.
- **`symmetricP1`** (Sakoe and Chiba 1978, `P = 1`, symmetric weights; the product's pattern): `g(i,k) = min(g(i−1,k−1) +
  2c(i,k), g(i−1,k−2) + 2c(i,k−1) + c(i,k), g(i−2,k−1) + 2c(i−1,k) + c(i,k))`, `g(0,0) = 2c(0,0)`. The slope stays
  between 1/2 and 2: never two horizontal or two vertical unit steps in a row. The path through a compound step lists its
  intermediate cell. A pair of lengths where no such path exists (`m − 1 > 2(n − 1)` or the reverse) gives `no_path`.
  Each row depends only on the two rows before it, so a row is computed in one vectorised NumPy step over the band.
- **Result:** `path (L, 2)` int64 `(i, k)` from `(0, 0)` to `(n−1, m−1)`; `distance = Σ c(path) / L`; `accumulated = g(n−1,
  m−1)` and `normalised = accumulated / (n + m)` for `symmetricP1` (the pattern's own normaliser) or `/ L` for `symmetric1`;
  `status` `ok`, or `no_path` (with `distance = None`, an empty path) when no finite path exists (`+inf` cells or the band
  or the slope); `params` echo `band`, `step`, `n`, `m`.
- **Ties** are broken in a fixed order (the diagonal first) so the result is deterministic.
- **Refusals** (`CompareError`): not a 2-dimensional float array, NaN, a negative value, `-inf`, an empty side, an unknown
  step, a band outside `(0, 1]`.

   path in a tie (the length changes), so the independent reference in the test follows the same documented order and
   the tests also check, without that order, that the returned path is a minimal one.
3. **One-row or one-column matrices**: the plan's `|i/(n−1) − k/(m−1)|` with a coordinate of 0 for a single row or column
   means a `1 × m` matrix with `band < 1` has no allowed end cell (`no_path`), and `symmetricP1` has no path for a
   `1 × m` with `m > 1` (slope). "A band never excludes the corners" holds for `n, m >= 2` only; the docs say so.
4. **`params`** is a read-only mapping with the keys `band`, `step`, `n`, `m` (as `Alignment.settings` of P6.03b), `band`
   echoed as a float.
5. **Dtype**: any floating dtype is accepted and computed as float64; integer, bool and object arrays are refused (the plan
   says "not a 2-dimensional float array").
6. **Band in the DP**: a cell outside the band is `+inf`; a compound step's intermediate cell must be allowed too, so every
   cell of the returned path is in the band (T-CMP-03b).

Phụ lục C viết `i/n`; dùng `n−1` và `m−1` thì hai góc `(0,0)` và `(n−1,m−1)` luôn nằm trên đường chéo nên với `n, m ≥ 2` band không bao giờ loại điểm đầu hay điểm cuối của đường căn; ma trận một hàng hoặc một cột không có đường chéo, với `r < 1` thì không có đường (`no_path`). **Hai step pattern:** `symmetric1` (bước đơn vị, `g = c + min(g(i−1,k−1), g(i−1,k), g(i,k−1))`, không giới hạn độ dốc, chuẩn hóa theo độ dài đường; là mẫu cổ điển mà `dtaidistance` chạy, chỉ để đối chiếu cài đặt) và `symmetricP1` (Sakoe-Chiba 1978, `P = 1`, trọng số đối xứng, **mẫu của sản phẩm**: `g(0,0) = 2c(0,0)`, `g(i,k)` là min của `g(i−1,k−1) + 2c(i,k)`, `g(i−1,k−2) + 2c(i,k−1) + c(i,k)` và `g(i−2,k−1) + 2c(i−1,k) + c(i,k)`; độ dốc luôn trong [1/2, 2], không bao giờ hai bước ngang hay hai bước dọc liên tiếp; chuẩn hóa `n + m` vì tổng trọng số của mọi đường là `n + m`). Hai chiều dài với `m−1 > 2(n−1)` hoặc ngược lại không có đường theo `symmetricP1`. Ô ngoài band hay `+inf` không dùng được, kể cả làm ô giữa của bước ghép; đường căn **liệt kê cả ô giữa** của bước ghép, nên mọi bước của đường là một trong `(1,1)`, `(1,0)`, `(0,1)` và mọi ô nằm trong band. **Kết quả:** `D = Σ c(path) / len(path)` (Phụ lục C.4) là trung bình **không trọng số** của chi phí trên các ô đã liệt kê; `accumulated` là chi phí cuối của DP (có trọng số của mẫu) và `normalised` là `accumulated` chia chuẩn hóa của mẫu, nên với `symmetricP1` `normalised` khác `D` (hai số không thay nhau được; P6.06 chỉ so các `D` làm cùng mẫu và cùng band, `params` ghi lại để từ chối trộn). Khi hòa, một thứ tự cố định cho kết quả xác định: `symmetric1` chéo, rồi `(i−1,k)`, rồi `(i,k−1)`; `symmetricP1` bước chéo, rồi bước từ `(i−1,k−2)`, rồi bước từ `(i−2,k−1)`; chi phí tích lũy không phụ thuộc thứ tự này nhưng `D` có (độ dài đường đổi). Không có đường hữu hạn (ô `+inf`, band, độ dốc) là một **kết quả**, `status = "no_path"`, đường rỗng và `distance`, `accumulated`, `normalised` đều `None` (không đưa ra con số mà ai đó có thể cộng hay so sánh nhầm); đối số sai (NaN, số âm, `−inf`, mảng không phải 2 chiều số thực, rỗng, step lạ, band ngoài (0, 1]) là `CompareError` nêu tên đối số. **Kiểm tra:** T-CMP-05 so với một cài đặt độc lập viết trong test (đệ quy có nhớ qua mọi ô, band bằng số học chính xác `Fraction`; 480 ma trận ngẫu nhiên cỡ 1–40, band 0,1–1, có ô `+inf`, một nửa là số nguyên để có hòa) vì `dtaidistance` chưa cài (cài làm dependency phát triển chờ maintainer); 900 × 900 với `r` = 0,2 và `symmetricP1` mất 0,03–0,08 s nên chưa cần Numba. ### 9.d Decision text (for `DECISIONS.md`, `DEC-NNNN`)

**P6.03a details of the DTW core (`compare/dtw.py`):** (1) a comparison with no finite path (`+inf` cells, the band or the slope) is the result `status = "no_path"` with an empty path and `None` for `distance`, `accumulated` **and** `normalised` (overview §3.3 named only `distance`); (2) `D` is the **unweighted** mean of the cost over the listed cells (Appendix C.4 read literally, the middle cells of compound steps included), so with `symmetricP1` it is not `normalised` (the weighted total over `n + m`); consumers compare `D` with `D` made with the same `params`; (3) ties go to the diagonal first, then (`symmetric1`) `(i-1, k)` then `(i, k-1)`, or (`symmetricP1`) the step from `(i-1, k-2)` then the step from `(i-2, k-1)`: a fixed order, because `D` depends on which tied path is returned; (4) the band uses `n - 1` and `m - 1` (Appendix C writes `n`, `m`) with 1e-12 of tolerance, so the corners are always in the band for `n, m >= 2` and a cell exactly on the edge is in; a single row or column has no diagonal and with a band below 1 has no path; (5) `params` is a read-only mapping (`band` as float, `step`, `n`, `m`); (6) `dtaidistance` is not added: T-CMP-05 is an independent recursion in the test (Q3 default; the dev-dependency question stays with the maintainer). **Reason:** a `None` cannot be added or compared by mistake where `inf` could; the literal Appendix C.4 definition is what the plan and the tests name; a fixed tie order makes a result reproducible; the corners rule keeps a path possible for any band. **Who asked:** the maintainer asked on 2026-11-17 to start the parallel tasks with subagents after reading the plans, so the defaults of Q1 to Q5 apply (DEC-0064). | ACCEPTED | `Docs/tasks/P6.03a.md`
