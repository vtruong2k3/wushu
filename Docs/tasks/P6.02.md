## 1. Analysis

### 1.1 Goal

The matrix of Appendix C.2 between every frame `i` of a query segment and every frame `k` of a reference segment:
`c(i, k)` is the weighted mean, over the feature units valid in both frames, of the distance between their 2-vectors; it is
`+∞` when fewer than `min_visible` units are valid in both. P6.03a runs DTW on it; P6.03b builds it from two segments.

### 1.2 Facts read (2026-11-17)

- Plan row: "masked cost matrix (`min_visible`, joint weights)", output `compare/dtw.py`, test T-CMP-02 ("a masked joint
  takes no part in the cost; too few valid joints give a cell of ∞").
- Appendix C.2: `c(i,k) = mean_{j valid in both} w_j · ‖f_j(i) − f_j(k)‖`; `+∞` when the common valid joints are fewer than
  `min_visible`; `w_j` chosen by the coach and A per action.
- P6.01 (plan): `FrameFeatures.values (N, U, 2)`, `valid (N, U)`, units in a fixed order (positions, then angles), NaN where
  invalid; positions in trunk lengths, angles as `(sin φ, cos φ)`.
- Sizes: a Taiji movement segment is about 5 to 30 s, 150 to 900 rows at 30 fps; a full 3-dimensional array
  `(n, m, U, 2)` of 900 × 900 × 21 × 2 float64 is 270 MB, so the computation goes by blocks of query rows.

### 1.3 Scope

**In:** `compare/cost.py`: `CostMatrix` and `cost_matrix(reference, query, *, min_visible, weights=None)`; tests T-CMP-02a..h;
a golden test on SYN-10; mutation check; docs. **Out:** DTW (P6.03a), the alignment of two segments (P6.03b), the choice of
weights per action (the coach's, later), any file on disk.

### 1.4 Interface

```python
@dataclass(frozen=True, eq=False)
class CostMatrix:
    values: np.ndarray        # (n, m) float64: axis 0 the query rows i, axis 1 the reference rows k; +inf, never NaN
    n_common: np.ndarray      # (n, m) int16: the weighted units valid in both frames
    units: tuple[str, ...]    # the names of the units, in the features' order
    weights: tuple[float, ...]  # as used, one per unit (0: left out)
    min_visible: int
    query_recording_id: str; reference_recording_id: str; feature_version: str

def cost_matrix(reference: FrameFeatures, query: FrameFeatures, *, min_visible: int,
                weights: Mapping[str, float] | None = None, block_rows: int = 64) -> CostMatrix
```

Per unit `u`: `d_u(i, k) = ‖q_u(i) − r_u(k)‖`: a distance in trunk lengths for a position; for an angle the chord between
the two unit vectors, `2 |sin(Δφ / 2)|`, from 0 to 2 (no angle is unwrapped). Cell: `Σ_u w_u d_u / Σ_u w_u` over the units
with `w_u > 0` valid in both frames, `+∞` when their count is below `min_visible`.

### 1.5 Conventions fixed by this task

1. The two feature sets must have the same units (names, kinds, order) and the same feature version; otherwise
   `CompareError` (no silent intersection).
2. A unit of weight 0 is left out (neither in the mean nor in the count); weights default to 1 for every unit; a weight
   is finite and `>= 0`, and at least `min_visible` units have a weight above 0.
3. `min_visible` is a required integer `>= 1` (no default, overview §3.5).
4. The values are never NaN: a cell is a finite mean or `+∞`.
5. The result does not depend on `block_rows` (a test runs 1, 7 and all rows).

Details this task adds inside the contract (none changes a field or a meaning of §3.2 of the overview):

1. **A partial `weights` mapping.** Plan §1.5.2 fixes the default (1 for every unit) but not a mapping that names only some
   units. Accepted default taken: **a unit that is not named keeps weight 1**; an unknown name is refused, so a typo
   never passes. The weights as used (one per unit, in the units' order) are echoed.
2. **Scale-free weights.** The mean is computed with the weights divided by their largest, so that a weight of 1e308 cannot
   overflow a sum; the result is the same mathematically (the mean is invariant to a common factor) and the echoed
   weights are the ones the caller passed. A positive weight that is below the largest by a factor so large that the
   ratio underflows to 0 is refused (its cell could otherwise divide by 0 and give NaN, and the contract says never
   NaN).
3. **Guards on the input features** (so that NaN can never reach the matrix): `values` must be a 3-dimensional float
   array with a last axis of 2, `valid` a bool array of the shape `values.shape[:2]`, `len(units)` equal to the second
   axis, and every component where `valid` is true must be finite (a valid feature with NaN is a defect of the producer,
   refused instead of passed on). Cells where `valid` is false are never read: they may hold NaN, a number or `inf`.
4. `block_rows` is an integer at least 1 (refused otherwise).
5. `data_sources` is not carried by `CostMatrix` (the plan's fields are the contract); P6.03b's `Alignment` holds both
   `FrameFeatures`, which carry them (AGENTS.md 9.4.6), noted for the coordinator in section 9.

### (d) DEC text (English, in the style of the DECISIONS table)

**The masked cost matrix (P6.02, `compare/cost.py`):** (1) a cell is the **weighted mean** `Σ w d / Σ w` of the unit distances over the units with a weight above 0 that are valid in both frames (Appendix C.2 read so that `D` does not grow with the number of units that happen to be valid, nor with a common factor of the weights), and `+inf` when fewer than `min_visible` units are common; never NaN; (2) the distance of a unit is the norm of the difference of the two stored 2-vectors: a distance in trunk lengths for a position, the chord `2 abs(sin((a - b) / 2))` (0 to 2) for an angle, never an unwrapped angle; (3) `min_visible` is a required integer from 1 to the number of units with a weight above 0 and counts every unit, positions and angles alike; (4) a weight of 0 leaves a unit out of the mean and of the count; weights default to 1 for every unit, a mapping names only the units to change (an unknown name is refused, an unnamed unit keeps 1), and the mean is computed with the weights divided by the largest so that no sum overflows (a share that underflows to 0 is refused); (5) **rows are the query and columns the reference**; (6) two feature sets with different units (kind, name, joints, order) or versions are refused, never intersected; the features are checked (shapes, a bool mask, a finite value wherever valid) so that NaN cannot enter the matrix; (7) the matrix is built by blocks of 64 query rows and never as the `(n, m, U, 2)` array; the result does not depend on the block size; (8) the value stored under a false mask is never read, and a bridged feature is a value like any other; (9) `data_sources` is not carried (the alignment of P6.03b holds both `FrameFeatures`, which carry them). **Measured:** 219 unit tests and 9 golden tests; 900 x 900 x 21 units in 0.31 s and 29 MB at the peak; ### (f) Bugs and findings (IDs left blank for the coordinator)

1. **Title:** a huge integer where a number is expected raises `OverflowError` instead of `CompareError` (`compare/dtw.py` and `compare/features.py`).
   **Severity:** S3 (minor: an absurd argument gives the wrong exception class, no wrong result). **Found in:** `compare/dtw.py` (`_check_band`) and
   `compare/features.py` (`_roll`, `_minimum`), found by the P6.02 agent on 2026-11-17 while writing the same guard for the weights of `cost.py`.
   **Minimal reproduction:** `dtw(np.zeros((3, 3)), band=10**400, step="symmetric1")` raises `OverflowError: int too large to convert to float`
   (also `band=-10**400`); `_roll(10**400)` and `_minimum(10**400, "min_scale_s", "seconds")` of `compare/features.py` raise the same.
   **Expected:** `CompareError` naming the argument (`dtw` documents "`CompareError` for a band outside (0, 1]"). **Actual:** `OverflowError`.
   **Root cause:** `float(value)` is called on an integer before the value is checked (`_is_number` accepts `int`).
   **Fix plan:** convert once with a helper that turns `OverflowError` into an infinite value (as `_as_float` in `cost.py` does) or compare an
   `int` as an integer before converting; the owners are P6.03a (`dtw.py`) and P6.01 (`features.py`).
   **Regression test:** `dtw(..., band=10**400)` and `frame_features(layer, roll_deg=10**400)` and `min_scale_s=10**400` raise `CompareError`.

   valley along the anti-diagonal (at most 0.0185 against 0.0000 on the diagonal), so the band and the slope pattern of DTW are what choose the
   right valley; a band of 1 (no band) may follow the wrong one. Worth a test in P6.03b (golden SYN-10 with `band` 1 and with `band` 0.2).
