## 1. Analysis

**Goal:** one logging setup for the whole code base (`logging` from the standard library). Every line carries a
timestamp with timezone, level, logger name and the `run_id` of the run it belongs to. Every run writes its own log
file. No log line, traceback included, contains an absolute filesystem path, because paths are the one channel through
which a real name (a video file or user-profile folder named after a person) can reach the logs.

hoặc đường dẫn có tên; có `run_id`". **Risk row (§18):** "Rò dữ liệu cá nhân — Log/file có tên thật — Test T-CORE-01,

**Inputs / outputs / interfaces:**

- Log line format (console and file, one record per line, tracebacks continue on the following lines):
  `2026-11-15T10:22:03.123+07:00 INFO     taiji_ai.pose.runner [run=3f2a9c01b7de] pose done in 41.2 s`
  — ISO-8601 local time with UTC offset and milliseconds, level padded to 8, logger name, the first 12 characters of
  `run_id` (`-` outside a run), message. The full `run_id` is written once, in the run's start line.
- Per-run file: `<run_dir>/run.log` (`data/runs/<run_id>/run.log` once P7 exists), UTF-8, opened in append mode, so
  a resumed or retried run (TECH_WORKFLOW §4.3) adds a new `run log start` block after the old one.
- Redaction placeholders (Windows and POSIX separators kept as written):

  | Placeholder | Root it replaces | Tail kept? |
  | --- | --- | --- |
  | `<data>` | `Settings.data_dir` | yes (`<data>\runs\<id>\pose_raw.npz`) |
  | `<models>` | `Settings.models_dir` | yes |
  | `<web>` | `Settings.web_dist_dir` | yes |
  | `<project>` | `config.PROJECT_ROOT` (`taiji_ai/`) | yes (`<project>\src\taiji_ai\api\app.py`) |
  | `<venv>` | `sys.prefix` | yes |
  | `<python>` | `sys.base_prefix` | yes |
  | `<path>` | any other absolute path (drive, UNC, `\\?\`, POSIX personal prefixes) | **no** — the whole path, up to a quote, `<`, `>`, pipe, `*`, `?` or the end of the line (stop rule revised by the review, BUG-0014) |

  The most specific (longest) root wins, so `<data>` beats `<project>` when `data/` is inside the project.
  A root is ignored when it is a drive/filesystem anchor, or equal to or an ancestor of the home folder or the temp
  folder (for example `TAIJI_DATA_DIR=C:\Users\X`): keeping its tail would expose everything under the profile.

## 2. Plan

### 2.1 Design

```text
entry point (python -m taiji_ai.api | future worker main)
  └─ configure_logging(settings)            # once; idempotent
       root logger ── level = settings.log_level
         └─ StreamHandler(stderr)  [marked as ours]
              filters:   RunContextFilter   (record.run_id = context var or "-")
              formatter: RedactingFormatter (ISO-8601 time, format above, PathRedactor on the whole text)
       logging.captureWarnings(True)        # warnings → logger "py.warnings" → same handler

  worker / stage runner (P7)
  └─ with run_log(run_dir, run_id, settings):
       context var RUN_ID = run_id
       root += FileHandler(run_dir/"run.log", append, utf-8)
                 filters:   RunContextFilter, RunMatchFilter(run_id)   # only this run's records
                 formatter: RedactingFormatter
       INFO "run log start: run_id=<full> taiji_ai=<version> pid=<pid>"
       ... stage code logs normally (getLogger(__name__)) ...
       INFO "run log end: ok"   |   ERROR "run log end: <ExceptionType>" then re-raise
       finally: remove + close handler, reset context var

uvicorn: server_config() passes log_config=None → uvicorn.error / uvicorn.access propagate to the root handler.
API boundary: exception text shown to a client goes through PathRedactor first (BUG-0011).
```

Public API of `taiji_ai/logs.py` (signatures are the contract for P7):

```python
RUN_LOG_NAME: Final = "run.log"
NO_RUN: Final = "-"
LOG_FORMAT: Final = "%(asctime)s %(levelname)-8s %(name)s [run=%(run_id).12s] %(message)s"

class PathRedactor:
    def __init__(self, roots: Mapping[str, str | os.PathLike[str]]) -> None: ...   # label -> folder
    @classmethod
    def for_settings(cls, settings: Settings) -> PathRedactor: ...
    def redact(self, text: str) -> str: ...

class RunContextFilter(logging.Filter): ...      # sets record.run_id if missing; always returns True
class RunMatchFilter(logging.Filter): ...        # True only when record.run_id == the run's id
class RedactingFormatter(logging.Formatter): ... # formatTime -> ISO-8601 with offset; format() -> redact(full text)

def configure_logging(settings: Settings | None = None, *, level: str | int | None = None,
                      stream: TextIO | None = None) -> logging.Handler: ...
@contextmanager
def run_log(run_dir: str | os.PathLike[str], run_id: str, settings: Settings | None = None) -> Iterator[Path]: ...
def current_run_id() -> str | None: ...
```

Behaviour details:

1. **`PathRedactor.redact`**, two passes over the text — *superseded 2026-11-15 by the review (BUG-0014/0015): one
   left-to-right pass finds each path start (known root first, then device, drive, UNC, and POSIX personal prefixes
   only with POSIX path syntax, default off on Windows), ends the span at the matching closing quote (`'` closes only
   when no letter/digit follows) or a stop character, an unquoted unknown path at the end of the line, an unquoted
   known-root tail at whitespace; spans are never rescanned. Rules in the `taiji_ai.logs` docstring.* Original text:
   - Pass 1, known roots: each root is resolved (`Path.resolve()`, non-strict) and matched in three spellings
     (`\`-separated, `/`-separated, and the doubled `\\` that `repr()` produces), case-insensitively on Windows.
     A match must end at a boundary (end of text, a separator, whitespace, a quote, `<>|,;:)]`), so `…\data2` is not
     `<data>` + `2`. Longest root first. Replacement: the placeholder; the tail stays.
   - Pass 2, any remaining absolute path, replaced by `<path>` up to a stop character (`'`, `"`, CR, LF, `<`, `>`, `|`,
     `*`, `?`) or the end of the line:
     Windows drive `(?<![A-Za-z0-9])[A-Za-z]:[\\/]` (so `http://` and `12:30` are not paths), long-path and device
     prefixes `\\?\`, `\\.\`, UNC `\\server\share` (also in repr form), POSIX personal prefixes `/home/`, `/Users/`,
     `/root/`, `/tmp/`, `/var/folders/`, `/private/`, `/mnt/`, `/media/`, `/Volumes/`, `/run/user/`. Other POSIX
     absolute paths are kept, because `/api/health` and URL paths must stay readable; the product runs on Windows.
2. **`RedactingFormatter.format`** calls `super().format(record)` (message + `exc_text` + `stack_info`) and redacts the
   final string, so tracebacks are covered. It sets `record.run_id = "-"` if no filter did. `formatTime` returns
   `datetime.fromtimestamp(record.created).astimezone().isoformat(timespec="milliseconds")`.
3. **`configure_logging`**: `settings or get_settings()`; level from the argument or `settings.log_level`, validated
   against `logging.getLevelNamesMapping()` → `ValueError("TAIJI_LOG_LEVEL must be one of DEBUG, INFO, WARNING,
   ERROR, CRITICAL; got 'X'")`. Removes and closes only handlers it installed before (marker attribute), adds one new
   one, sets the root level, turns on `captureWarnings`. Returns the handler. Never calls `basicConfig`; never touches
   other handlers or third-party logger levels.
4. **`run_log`**: `run_id` must match `^[A-Za-z0-9_-]{1,64}$` (it becomes part of a path and of every line) →
   `ValueError`. Nested use → `RuntimeError("run_log() is already active for run …")`. Called before
   `configure_logging()` → `RuntimeError("call taiji_ai.logs.configure_logging() first")`, because otherwise the root
   level (WARNING by default) would silently drop INFO lines. Creates `run_dir` if missing; an `OSError` opening the
   file propagates.
5. Library modules keep `log = logging.getLogger(__name__)` and never configure logging. Only entry points call
   `configure_logging` (today: `python -m taiji_ai.api`; later: the worker).

### 2.7 Logging rules (to be copied into the module docstring and, if Q4, AGENTS.md §6)

1. Library code: `log = logging.getLogger(__name__)`; never `print`, never `basicConfig`, never add handlers.
2. Log IDs: `run_id`, `recording_id`, `segment_id`/revision, participant **pseudonym**, `take_id`, a SHA-256 prefix.
   Never a user-supplied file name or path, never free text typed by a person (notes, labels), never frame data.
3. Paths inside our folders are fine (they are redacted to `<data>\…`); still prefer IDs.
4. No per-frame INFO lines. Progress: at most one line every few seconds.
5. Exceptions: `log.exception(...)` in the handler that decides what happens next; do not log and re-raise the same
   error at every level.
6. The API never returns exception text to a client unless it went through `PathRedactor` (error codes preferred,
   T-API-02).

  the manifest status, exit non-zero; no traceback printed outside logging. Redirect or silence `rtmlib`'s stdout
  prints there.
- **P7.02 stage runner:** one INFO line per stage start/end with duration; no per-frame lines.
- **P3.02 pose runner:** threads (if any) start through `contextvars.copy_context().run`, otherwise their lines miss
  `run.log` (R5).
- **P2.02 ingest:** log `recording_id` and the SHA-256 prefix, never the source file name (it may hold a real name);
  redaction is the safety net, not the policy. `ProbeError` texts contain the source path: never return them to a
