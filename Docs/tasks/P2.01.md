## 1. Analysis

**Goal:** fix the data contracts of Phase 2 before any code writes them: what `recording.json` and `sync.json` contain,
which values are allowed, how a camera's time maps to the other camera's time, and which field goes to which database
column. Everything later (P2.02–P2.06, P3, P8) reads these files.

**Facts read (2026-11-15):**

- `TECH_WORKFLOW_V1.md` §4.2 gives a `recording.json` example (`schema_version` `recording/1`, `recording_id`, `sha256`,
  `participant_id`, `session_id`, `take_id` `S01-P03-T02`, `camera_id` `camA`, `consent_ref` `CONSENT-2026-011`, size,
  `display_rotation`, `time_base` `"1/90000"`, `nominal_fps`, `vfr`, `duration_s`, `has_audio`, `ingested_at` with a time
  zone). §4.1: `data/recordings/<recording_uuid>/{source.<ext>, recording.json, pts.parquet, proxy.mp4, audio.wav}` and
  `data/takes/<take_id>/sync.json`. §4.4: atomic writes, manifest last. W2: `drift = (offset_end − offset_start) / duration`,
  `t_cam2 = t_cam1 + offset_start + drift × (t_cam1 − t0)`, validation by flash, `sync.json` with `method`, `offset`,
  `drift`, `residual_ms`, `validated_by`.
- `migrations/0001_init.sql`: `recording` (`recording_id` PK, `participant_id` FK → `participant`, `session_id`, `take_id`,
  `camera_id`, `sha256` UNIQUE, `source_path`, `width`, `height`, `rotation`, `nominal_fps`, `vfr`, `duration_s`,
  `has_audio`, `ingested_at`); `sync` (PK `take_id`, `cam_a`, `cam_b`; `offset_s` NOT NULL, `drift` NOT NULL DEFAULT 0,
  `residual_ms`, `method`, `validated_by`, `created_at`).
- `io/probe.py` `VideoMeta` (codec, size, `time_base` string, `r_frame_rate`, `avg_frame_rate`, `duration_s`, `nb_frames`,
  `rotation` in {0, 90, 180, 270}, `has_audio`, `start_time_s`); `io/frames.py`: time convention
  `t_sec = (pts − stream_start_pts) × time_base`, seconds from the first video PTS.
- The capture protocol (P1.05) names the IDs (`S01`, `P03`, `S01-P03-T02`, `camA` / `camB`) and leaves camera role, height,
  distance and form direction "for P2.01" (no database column). The consent form (P1.06) uses `CONSENT-YYYY-NNN`.
- AGENTS.md §6: Pydantic v2, `schema_version` in every persisted manifest; §5.4 units documented; §5.1 no fabricated values.

**Problems the design must solve (found while reading):**

1. W2's mapping does not say what `t0` is or which camera is "1"; a sign error here moves every comparison by the offset.
2. `sync.drift` is NOT NULL DEFAULT 0 in the database, but a take can have a start match and no end match: the drift is then
   unknown, and storing 0 would be a fabricated value (§5.1). Decided in Q4.
3. The camera of a calibration clip (`S01-CB-T01`, P1.05 §6) has no participant, while `recording.participant_id` is NOT NULL
   with a foreign key. Decided in Q3.
4. The original file name of the phone is user-supplied text; it must not reach logs (AGENTS.md §6) and is not needed in the
   manifest: the capture sheet keeps the mapping.

**In scope:**

- `schemas/_base.py`: `Manifest` base (Pydantic v2, `extra="forbid"`, frozen), helpers `write_manifest(path, model)` (atomic,
  via `store.artifacts`) and `read_manifest(path, cls)` (validates; raises `ManifestError` naming the field).
- `schemas/recording.py`: `IngestMeta` (the input of P2.02: IDs + optional `CaptureInfo`), `CaptureInfo`, `RecordingManifest`
  (`recording/1`), `ProxyManifest` (`proxy/1`, Q1), and the mapping to the `recording` columns.
- `schemas/sync.py`: `SyncWindow`, `SyncValidation`, `SyncManifest` (`sync/1`), the time mapping `a_to_b(t)` / `b_to_a(t)`.
- Unit tests T-SCH-01a..h.

**Out of scope:** writing these files (P2.02–P2.06), a database migration (Q4), segment, run and metric schemas (P5, P7, P8).

**Design (fields; units in brackets):**

`RecordingManifest` (`schema_version: "recording/1"`):

| Group | Fields |
| ----- | ------ |
| Identity | `recording_id` (UUID4 string), `sha256` (64 hex), `participant_id` (`P\d{2,}`), `session_id` (`S\d{2,}`), `take_id` (`<session_id>-<participant_id>-T\d{2,}`, checked against the two), `camera_id` (`cam[A-Z]`), `consent_ref` (`CONSENT-\d{4}-\d{3,}`) |
| Source | `source_ext` (`.mp4` / `.mov` / …), `size_bytes`, `container` (ffprobe `format_name`), `codec`; **no original file name** |
| Picture | `width`, `height` [px, coded], `display_rotation` [deg, one of 0/90/180/270] |
| Time | `time_base` (string fraction), `start_pts` [ticks], `n_frames`, `pts_span_s` [s, last − first PTS], `duration_s` [s, container, nullable], `nominal_fps` [Hz, container `avg_frame_rate`], `r_frame_rate` [Hz], `measured_fps` [Hz, 1 / median dt], `median_dt_s`, `dt_rel_std`, `n_duplicate_pts`, `vfr` (bool), `vfr_rule` (name, `rel_tol`, tick tolerance, version: BUG-0046) |
| Audio | `audio`: `null` or {`codec`, `sample_rate` [Hz], `channels`, `start_offset_s` [s, audio start − video start]} |
| Capture | `capture`: optional `CaptureInfo` {`camera_role` (`main_axis` / `side_left` / `side_right`), `height_m`, `distance_m`, `fps_setting`}; structured only, no free text |
| Provenance | `ingested_at` (aware datetime, ISO with offset), `tools` {`ffprobe`, `pyav`, `taiji_ai`} versions |

`SyncManifest` (`schema_version: "sync/1"`), one per `take_id` and camera pair:

- `take_id`, `cam_a`, `cam_b` (`cam_a` sorts before `cam_b`; `camA` is the reference), `recording_id_a`, `recording_id_b`.
- **Time mapping (fixes problem 1):** times are seconds on each camera's own video timeline (the `frames.py` convention).
  `t_b = t_a + offset_s + drift × (t_a − t_ref_s)`, where `t_ref_s` is the centre of the matched start window on camera A;
  `drift` is dimensionless (s per s; 1e-4 = 100 ppm). Methods `a_to_b(t)` and `b_to_a(t)` (exact inverse).
- `method` (`audio_xcorr/1`), `params` (sample rate, envelope cut-off, window lengths, maximum lag), `start` and `end`:
  `SyncWindow` {`window_a_s` [t0, t1], `lag_s`, `peak` (normalised correlation), `peak_ratio` (best to second-best), `found`}.
- `status`: `ok` (start and end found), `start_only` (drift unknown), `not_found`; `offset_s` and `drift` are `null` when not
  known (validator: `not_found` ⇒ both null; `start_only` ⇒ drift null).
- `validation`: {`method` (`flash` / `none`), flash times per camera, `residual_ms`, `residual_frames`, `frame_dt_s`}.
- `usable_for_metrics` (bool) and `usable_reason` (enum); validator: `true` only with `status = ok`, `validation.method =
  flash` and `residual_frames ≤ 1` (the P2.06 rule; the number lives in one constant).
- `created_at`, `tools`.

`ProxyManifest` (`proxy/1`, Q1): `recording_id`, `source_sha256`, `proxy_sha256`, `height`, `rotation_applied`, `ffmpeg`
version, `args`, `n_frames_source`, `n_frames_proxy`, `check` {`points`, `max_abs_dt_s`, `max_abs_dt_frames`, `passed`}.

**Database mapping (`recording` row from `RecordingManifest`):** `recording_id`, `participant_id`, `session_id`, `take_id`,
`camera_id`, `sha256`, `source_path` (**relative** to the data folder: `recordings/<id>/source.<ext>`, never absolute),
`width`, `height`, `rotation` ← `display_rotation`, `nominal_fps`, `vfr`, `duration_s` (← `pts_span_s` + one `median_dt_s`
when the container has none), `has_audio` ← `audio is not null`, `ingested_at`.

## 3. Plan re-read (before coding)

- Plan re-read: 2026-11-15 — OK against the current files: `schemas/` holds only `ontology.py` (and an empty `__init__`),
  pydantic is 2.14.3 and has `AwareDatetime`, migration 0001 and `store.db.connect` are as described, `io/probe.py` and
  `io/frames.py` are unchanged. The maintainer's answers (DEC-0025): Q1–Q5 as the defaults.
- **Additions found at the re-read (the plan's steps stay):**
  1. P2.04's test "no audio stream: `not_found`, reason `no_audio`" needs a field the schema did not list: `not_found_reason`
     (`no_audio` or `clap_not_found`), required exactly when `status = not_found`.
  2. `IngestMeta` carries the four ID fields and the optional capture info, **not** `consent_ref`: the consent reference comes
     from the participant row at ingest time. The ID rules live once in a shared base `TakeIds` used by `IngestMeta` and
     `RecordingManifest`.
  3. The per-end flash results are kept (`residual_start_ms`, `residual_end_ms`, either may be null) and `residual_ms` is the
     larger absolute one; this makes the "flash found only at the start" case of P2.05 Q1 representable without a made-up
     number. `residual_frames` must equal `residual_ms / 1000 / frame_dt_s`.
  4. `a_to_b` / `b_to_a` raise `SyncUnavailable` unless `status = ok`: with an unknown drift a mapping would silently assume 0.
  5. One frame means no spread: `n_frames = 1` forces `median_dt_s`, `measured_fps` and `dt_rel_std` to be null and
     `pts_span_s` to be 0 (no invented interval).
  6. Floats reject NaN and infinity (`allow_inf_nan=False`), so every manifest is valid JSON; `ProxyManifest.args` rejects an
     absolute path (AGENTS.md §5.9); `passed = true` also requires equal frame counts (P2.03 test T-IO-10).
  7. Tests: the plan's T-SCH-01a..h plus T-SCH-01i (`IngestMeta`, `CaptureInfo`).

   `read_manifest` are functions. `parse_manifest` is new (the plan named only write and read) because the tests and P2.02
   validate dictionaries as well as files.
2. Rules added at the re-read (§3): `not_found_reason`, per-end flash residuals, `SyncUnavailable`, the one-frame rules, NaN
   refusal, no absolute path in `ProxyManifest.args`, equal frame counts for a passed proxy.

   the right rule. (c) `ProxyCheck.points` allowed 2 or more; it now allows 1 (a one-frame clip).
