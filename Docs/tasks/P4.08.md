## 1. Analysis

**Goal.** W6 was built and measured on pose from lesson **videos** (D20: 22 chunks, up to 9,061 rows, constant frame rate, everything observed or lost whole). P4.08 puts the **real, long, imperfect clocks and holes of another sensor** through the same chain: the UMONS Kinect V2 skeleton recordings at 30 Hz, 111 sequences, 703,146 rows, up to 11,790 rows each. The plan row asks that "mask, gap and filter do not break on a long sequence" (T-QLT-12: "a sequence of 4,000+ frames runs through the quality pipeline without error, the coverage is reasonable"). The task has three outputs: an **adapter** (`bench/umons.py`, strict reader and the mapping of a Kinect row to the layers the chain reads) that **P6.07 will reuse**, a **test** (synthetic Kinect-format text for the adapter, real files for the chain, skipped when the dataset is absent) and a **report** (`Docs/reports/p4_umons_quality.md`, numbers only). It changes **no stage** and makes no claim about Kinect accuracy or about Tai Chi quality: UMONS is 13 techniques, not the 24 forms, so it is out of domain for any product number (AGENTS.md 9.4.4) and is used as `dev-test` for the quality layer only.

**What the analysis measured** (read-only scripts in the scratch folder, nothing from the dataset copied into the repository; four probes over all 111 files; the chain of P4.07 with a throw-away adapter):

- **Format.** Every file has 76 numbers per row (a timestamp in **ms** and 25 joints x (x, y, z) in **mm**), no NaN. 111 Kinect files, 131 `.lab` files (20 labels have no Kinect file); rows per file min 1,360, median 5,832, max 11,790; **104 files have 4,000 rows or more**; duration 45 to 407 s. The joint order is the standard Kinect V2 `JointType` order (checked on the data: the spine base, mid, neck and head go up the vertical axis by 330 to 350 mm per joint; the left shoulder, elbow, wrist and hand lie on one side of the spine and the right ones on the other).
- **The frame of the coordinates.** `z` is vertical (in the first row the head is 858 mm above the spine base), `y` lateral, `x` the distance along the sensor axis (-4,821 to 0 mm; about -3,300 mm for the first sequence). So **(y, -z) is the image plane seen along the sensor**: the median torso (middle of the shoulders to middle of the hips) is 435 to 539 mm (median 455) in 3D and **0.971 to 1.000 of it (median 0.995) in that plane**; the dropped depth axis moves by 331 mm (median over files of p1 to p99) and up to 1,427 mm.
- **The clock is not uniform in any file.** Steps between rows: **683,568 of one frame (33 or 34 ms)**, **19,161 of 40 to 150 ms (one or more dropped frames)**, **275 pauses of more than 150 ms** (up to 733 ms), **31 repeated timestamps**, none backwards. The mean frame rate of a file is 21.9 to 30.0 Hz (median 29.4). **No file is within 1 ms of a straight line** (the largest deviation 13 s), so the **non-identity grid of P4.04 runs on every file**: the first real variable-frame-rate data of the project (DEC-0047 listed it as a limit: "no real VFR clip"). The long steps are real dropped frames: the mean joint displacement grows with the step (33 ms: 5.1 mm; 56 to 80 ms: 7.9 mm; 81 to 120 ms: 11.3 mm; 121 to 150 ms: 14.0 mm).
- **The 31 repeated timestamps are one defect in one file, `P04T02C03`: two skeletons per timestamp for about 60 rows (rows 9,585 to 9,643).** The second row of each pair differs from the first by a mean joint distance of **about 620 to 670 mm** while rows two apart (same body) differ by 2 to 8 mm: **a second body is in the picture and the file interleaves the two without saying which one is the performer** (the case W5 calls `ambiguous`). The chain needs strictly increasing times, so the adapter must decide what to do with such rows.
- **Zeros.** 16 joint cells (in one file, `P01T02C07`, the last rows) are exactly (0, 0, 0): the only "not tracked" marker the files have. No row has all 25 joints at zero. **The files have no confidence value, no tracking state and no NaN**: the Kinect output is always a complete skeleton.
- **What the chain does with it** (all 111 files; the adapter of the probe: the 17 HALPE joints that Kinect has, the plane (y, -z) in mm taken as pixels, a (0, 0, 0) joint not observed, score 1.0 for every other joint, the first row kept per repeated timestamp; default parameters):
  - **0 errors in 111 files; 703,115 rows in 30 s (0.43 s per 10,000 rows).**
  - Grid: 732,766 grid rows (+4.2 %: dropped frames become grid rows); **96.5 % of the grid rows are `mixed`** (the grid step is the median interval, 33 ms, against a true mean of 33.33 ms, and the timestamps are rounded to the ms, so the grid slides against the rows); with an explicit `grid_hz` = 30 (33.33 ms) 725,925 grid rows and **77.8 % mixed**. A mixed row is a flagged linear mix of two real frames: the report says so; it is not an error (DEC-0047, "a coarse time base"), but it means that on real sensor clocks almost nothing is a bit-exact copy.
  - Cells over 26 joints: 63.29 % observed, 1.868 % bridged, 34.84 % missing; **9 of the 26 HALPE joints do not exist in Kinect** (nose, eyes, ears, small toes, heels): 34.5 % of all cells are missing for that reason (`non_finite`, 6,578,337 cells; 999 gaps of outcome `open_both` = 9 joints x 111 files). **Over the 17 joints Kinect has: 96.80 % observed, 2.857 % bridged, 0.340 % missing.** Usable frames 99.75 % (per file min 90.69 %, p10 99.62 %); usable share of the 17 joints per file min 90.24 %, median 99.89 %.
  - **Hampel flags 367,011 cells (1.93 % of all cells, 2.8 % of the cells of the 17 joints; per file 1.2 to 5.5 % of those cells)**, against 0.19 % on the D20 video pose: wrists 4.2 %, toes 3.8 to 4.3 %, elbows 2.2 to 2.4 %, knees and ankles 1.3 to 1.6 %, trunk and head at most 0.25 %. Only 11,055 of them stay NaN; the rest are bridged (on the source rows 187,903 cells in 160,281 filled gaps; on the grid about twice as many bridged cells, 1.868 % of all cells, because a mixed grid cell built on a bridged cell is itself flagged bridged); 2,085 gaps are too long. What those flags are (real spikes or the jitter of the distal Kinect joints) is not decided by this task; the report states the numbers per joint.
  - **No-frame:** 47,866 cells (a pause of more than 150 ms is NaN `no_frame`, never bridged), in 54 files. Swap flag: 9 warnings in 7 files (6 `suspect` cells, 24 `blocked`). 10,494 usable cells are in runs too short to filter.
- **The nominal frame is not what the chain assumes for the Hampel floor**: the floor is 1 % of the torso, here 4.4 to 5.4 mm, which has no relation to any sensor noise; the stages are scale-free (the floor and the swap limit are torso-relative; gaps, grid and filter are in seconds; the mask reads a score), so reading mm as pixels changes nothing but the unit of `torso_px`.

**What is not obvious, and why this plan asks questions.**

- **A chain that "does not break" is a weak result by itself.** The Kinect file has no holes of its own (no NaN, 16 zero cells), so the mask and the gap layer have almost nothing to do on it; what is really exercised is the **grid on a real clock**, the **filter on long runs** (runs of thousands of rows; D20 had hundreds), the **swap flag and Hampel on a different sensor's errors** and the **report on 700,000 rows**. The report should say that plainly and not present the 96.8 % as a quality of the pose.
- **No score.** The chain reads a score; the file has none. A constant 1.0 for "the sensor reported this joint" is an assumption, not a measurement; it must be stated, and the mask then only removes the (0, 0, 0) cells and the nine joints that are absent. The alternative (derive a score from something) would be fabricating.
- **Absent joints.** Nine of the 26 are never observed. Counting them as `missing` is right (they are not measured) but it makes the 26-joint coverage meaningless (at best 65.4 %); the report must give the 17-joint numbers next to it.
- **`mixed` rows at 96.5 %.** Not a defect of this task; a property of P4.04 on a ms-rounded clock that the maintainer should see (Q6).

**The rules** (each has a test sub-ID below):

1. **Strict reader.** One row per non-empty line (LF or CRLF); exactly 76 whitespace-separated numbers; every one finite; at least one row; timestamps non-decreasing (a **decrease is an error** naming the row). The sequence id must match the pattern.
2. **The clock.** `t_sec = (ts - ts[0]) / 1000`, real timestamps as given: nothing is regularised (AGENTS.md 5.2). **A timestamp that occurs more than once** (two bodies in one frame): one row per timestamp is kept (the first), `tracked = False` for it, the other rows are dropped and counted (`repeated_rows`, `ambiguous_timestamps`); the file does not say which body is the performer, so nobody is taken (as W5's `ambiguous`); the chain sees a `not_tracked` row that it never bridges.
3. **The layers.** Kinect joint -> HALPE index: spine base -> `Hip` (19), neck -> `Neck` (18), head -> `Head` (17), shoulders, elbows, wrists -> 5/6, 7/8, 9/10, hips, knees, ankles -> 11/12, 13/14, 15/16, **foot -> big toe (20/21)** (an approximation: the Kinect foot joint is the forefoot); the spine mid, spine shoulder, hands, hand tips and thumbs have no HALPE joint and are dropped. **Absent HALPE joints** (nose, eyes, ears, small toes, heels: nine) are NaN with a NaN score (reason `non_finite`). Position = `(y, -z)` in mm, unchanged in scale (1 mm = 1 pixel, stated: no calibration).
4. **Scores.** A joint the file reports gets **1.0** (the file has no confidence: the value says "reported", not a probability); a joint at exactly (0, 0, 0) is not observed: NaN position and score 0.0 (reason `low_conf`); an absent joint, NaN (rule 3).
5. **The chain** is `run_quality_arrays` with `tracked`, no `in_segment` (the whole sequence), and the parameters given (default: `QualityParams()`); nothing is tuned for Kinect.
6. **The numbers** come from `QualityReport` only (the partition is asserted for every file while aggregating), plus the adapter counts; nothing but counts, shares and names leaves the module.
7. **A file that fails the reader or the chain is reported as an error row** with its exception; the run goes on; the tool exits non-zero if any file failed.
8. **`find_umons(root)`** accepts the dataset root or its `Kinect` folder and checks: exactly 111 files `P??T??C??.txt`, a `License.txt` that names CC BY-NC-SA 4.0; otherwise `UmonsError`.

**Existing code and docs read.** `Docs/IMPLEMENTATION_PLAN_V1.md` (P4.08, T-QLT-12, P6.07, P1.05 Q2), `Docs/DATASET_REGISTRY_TAIJI.md` (D12), `datasets/taiji/README.md` (format, provenance, license), `Docs/TECH_WORKFLOW_V1.md` (W5 `ambiguous`, W6 notes of P4.01 to P4.07), `Docs/tasks/P4.07.md`, DEC-0045 to DEC-0050, `taiji_ai/src/taiji_ai/quality/*` and `schemas/quality.py`, `bench/__init__.py` and `bench/clips.py` (how a third-party dataset is found and named), `tools/pose_audit.py` (how a tool wraps a library), `tests/golden/test_pose_d20.py` (the `dataset` marker and skipping), `pyproject.toml` (markers). **The dataset files were only read as text** (AGENTS.md 9.4.2 and 5.11: nothing from `datasets/` is executed).

**Constraints that apply** (AGENTS.md): 5.1 no fabricated data (a constant score is stated as a convention, not an observation; an ambiguous frame is not guessed; nothing is filled by the adapter); 5.2 real timestamps (the file's own, no regularisation, no assumed fps); 5.3 layers apart; 5.4 units documented (mm read as pixels, no calibration); **5.5** no universal threshold: the bounds of the dataset test are sanity bounds of data validity, not thresholds on a movement; 5.9 / 9.4: **dataset license CC BY-NC-SA 4.0**, tag `dev-test`: allowed; the repository keeps no dataset content (the tests that need the data are marked `dataset` and skip when it is absent; the adapter tests use text made in the test); derived numbers are statistics and carry the source (D12, license) in the report; Kinect is **not** a Taijiquan 24-form dataset (9.4.4): reported separately, never as product accuracy; 6 code conventions (type hints, docstrings with units, `UmonsError`, no `print` in `src/`, logs carry ids only); no code from `repos/` or `datasets/` is run.

**Unknowns, risks, questions** (the maintainer is asked; the proposed answer is applied if there is no other):

- **Q1. Scope and place.** The adapter is a library module `bench/umons.py` (P6.07 reuses it) with a thin `tools/umons_adapter.py`, as the plan row names; no stage is changed; a finding that is a defect becomes a bug or an ad-hoc task. **Proposed: yes.** Alternative: only the tool (P6.07 would copy or import from `tools/`).
- **Q2. The image plane.** **Proposed: (y, -z) in mm read as pixels**: it keeps 97 to 100 % of the torso (median 99.5 %), the stages are scale-free, and no calibration is invented. Alternatives: a pinhole projection with an assumed focal length (invented numbers), or the 3D coordinates (the chain is 2D).
- **Q3. The joints.** **Proposed: 17 of the 26 HALPE joints, foot -> big toe, the nine others absent (NaN, `non_finite`), the report gives the coverage over the 17 next to the 26.** Alternatives: leave the toes absent (15 joints: no foot swap pair), or define a Kinect-specific essential set (the default rule needs 5 of 10 essential joints and Kinect has 8 of them, so the default works as is).
- **Q4. The score.** **Proposed: 1.0 for a joint the file reports, 0.0 for a joint at (0, 0, 0), NaN for an absent joint; default `MaskParams`.** Alternative: none that is not invented.
- **Q5. Repeated timestamps (two bodies at once).** **Proposed: keep the first row of the timestamp, `tracked = False` (reason `not_tracked`, never bridged), count and report them.** Alternatives: choose the row that continues the previous one (that is W5's tracking, out of scope; it needs a cost and a threshold), drop both rows (the chain would see a pause of 2 s as `no_frame`), keep the first as valid (the chain would receive a 650 mm jump every other frame: Hampel and the swap flag would be tested on a glitch that is not their job).
- **Q6. The grid on a ms-rounded clock.** **Proposed: the baseline run uses the default chain** (what P7 will call), and the report adds a side measurement with `grid_hz` = 30 (the sensor's nominal rate: 77.8 % mixed against 96.5 %). **Decision wanted:** is "almost every grid row is a flagged mix on a real sensor clock" a defect to fix? If yes, register ad-hoc task **X.31** (not started; idea: a grid time within a tolerance of a source row copies that row instead of mixing, or the grid step comes from a robust mean; a change of DEC-0047, so it needs its own plan); if not, the report records it as a known property. P4.08 does not change P4.04 either way.
- **Q7. What the tests pin and where `.lab` stands.** **Proposed:** the gate runs six named real files (`P08T03C01`, the longest, 11,790 rows; `P04T02C03`, the two bodies; `P02T02C09`, a 733 ms pause; `P09T02C02`, the lowest coverage and 209 long steps; `P01T02C07`, the (0, 0, 0) joints; `P07T02C02`, three swap warnings) with sanity bounds only; the full run over 111 files is the tool and the report (about 30 s). The `.lab` labels and the per-class coverage (named intervals on real segments) stay with P6.07. Alternative: also use the `.lab` segments as named intervals now (it needs the alignment of the label times with the timestamps, which is a P6.07 question).
- **Risk: the sensor frame.** The plane (y, -z) was checked on the data (torso ratio 0.97 to 1.0), not on documentation; if a file has the body turned so that the plane foreshortens the torso, the ratio shows it (the report prints the median torso per file).
- **Risk: the dataset moves.** If the extracted folder differs (111 files and the license are checked, content is not), the strict reader and the numbers of the report would differ; the report states the file count and the dataset md5 of `Kinect.zip` from `datasets/taiji/README.md` (`d2802095beec3736ecfb35ab4eac70e8`).
- **Risk: gate time.** Six real files take a few seconds; the 111-file run is not in the gate.

## 2. Plan

**Design.**

```python
# taiji_ai/src/taiji_ai/bench/umons.py
class UmonsError(BenchError): ...
KINECT_JOINTS: Final[tuple[str, ...]]            # the 25 names of Kinect V2, in file order
KINECT_TO_HALPE: Final[dict[str, str]]           # Kinect name -> HALPE name (17 entries)
PROVIDED: Final[tuple[int, ...]]                 # the 17 HALPE indices that Kinect fills

@dataclass(frozen=True, eq=False)
class KinectSequence:                            # arrays read-only
    sequence_id: str; t_sec: ndarray; keypoints: ndarray; scores: ndarray; tracked: ndarray
    rows_in_file: int; repeated_rows: int; ambiguous_timestamps: int; zero_joint_cells: int

def parse_kinect(text: str, sequence_id: str) -> KinectSequence
def load_kinect(path: Path) -> KinectSequence                      # the id is the file stem
def find_umons(root: Path) -> Path
@dataclass(frozen=True) class SequenceResult: sequence_id, counts, report: QualityReport | None, error: str | None, seconds: float
def run_sequence(seq: KinectSequence, params: QualityParams | None = None) -> SequenceResult
def run_folder(folder: Path, params=None, names=None) -> list[SequenceResult]
def aggregate(results) -> UmonsSummary                              # sums, distributions, named files
def render_report(summary, params) -> str                           # Markdown, deterministic
```

Data flow: `find_umons` -> for each file `load_kinect` (strict) -> `run_quality_arrays` -> the report -> `aggregate` (partition asserted) -> `render_report` / CSV.
