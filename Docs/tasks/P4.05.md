## 1. Analysis

**Goal:** the fifth step of the quality layer (W6). Pose keypoints jitter by a pixel or two from frame to frame; the metrics of P5 (speed, pauses, amplitudes) are
sensitive to it. W6 asks for a **Butterworth low-pass of order 4, cutoff 6 Hz, zero phase (`filtfilt`), run separately on each continuous valid stretch**.
This task filters the grid layer of P4.04: a **run** is a maximal sequence of rows in which a joint has a value (observed or bridged); each run is filtered on
its own, so a NaN never leaks into a neighbour and nothing is filtered across a hole, a loss of the target or a pause. A run too short for the filter (at most
`padlen` rows) is **not** filtered and says so. The layers stay apart (AGENTS.md 5.3): raw, mask, gap and grid layers are read and never changed; the filtered
layer is new.

**What the analysis measured (numbers only, nothing committed):**

- **The filter itself (scipy 1.18, `butter(4, 6, fs, output="sos")` and `sosfiltfilt`).** `padlen` is **15** for order 4 at every sampling rate (two sections),
  and a run must be **longer** than it: 15 rows are refused, 16 are accepted. Because it is applied forward and backward the gain at the design frequency is
  exactly **0.500 (-6 dB)**, and the -3 dB point of the zero-phase filter is at **5.58 / 5.51 / 5.41 Hz** for 24 / 30 / 60 fps (so "6 Hz" is the design frequency of
  one pass, not the half-power frequency of the result: this goes into the documentation). A constant stays exactly constant, a straight line is kept (0.002 px
  at the ends of 90 rows), a 1 Hz sine of 100 px keeps to 0.0001 px inside and 0.17 px at the two ends; a step of 100 px rings by **8.2 px** on both sides (so a jump
  that Hampel did not remove is smeared, not removed). The white-noise standard deviation falls to **0.68 / 0.66 / 0.60 / 0.42** of its value at 24 / 25 / 30 / 60 fps:
  at lesson frame rates a 6 Hz cutoff takes out about a third of white jitter, because the band up to Nyquist is only 12 Hz. At **10 fps** (Nyquist 5 Hz) the design
  fails (`Wn < fs / 2`): such a clip cannot be filtered at 6 Hz.
- **The runs of the real footage** (D20 pass of P3.08, N = 1, 22 chunks, after mask, Hampel with the defaults, the gap layer and the identity grid): **965 runs**, **2,249,882
  usable cells**; median run **1,829 rows**, longest 8,643. Runs of at most 15 rows: **87 runs (9 % of the runs) but only 231 cells (0.010 % of the cells)**; by length
  (runs / cells): 1 to 3 rows 70 / 79, 4 to 8 rows 9 / 50, 9 to 15 rows 8 / 102, 16 to 30 rows 4 / 84, 31 to 100 rows 20 / 1,230, over 100 rows 854 / 2,248,337. So on this
  footage the "too short" case is rare and costs almost nothing.
- **What the filter does to the real movement** (the same runs of 16 rows or more; `|filtered - input|` in px, % of the torso (191 px) at p95, the ratio of the
  root-mean-square second difference after and before (the jitter), the ratio of the p99 speed after and before, both as medians over the runs):

  | cutoff | p50 px | p95 px (% torso) | p99 px | jitter after / before | p99 speed after / before |
  |---|---|---|---|---|---|
  | 4 Hz | 1.02 | 4.48 (1.85) | 9.18 | 0.167 | 0.717 |
  | **6 Hz** | **0.83** | **3.76 (1.53)** | **7.54** | **0.316** | **0.769** |
  | 8 Hz | 0.68 | 3.23 (1.29) | 6.59 | 0.507 | 0.836 |

  At 6 Hz by group, p95 in px: head 2.96, trunk 3.03, arms 5.77, legs 3.22, feet 4.13 (arms 2.3 % of the torso). The cells within 10 rows of the end of a run move more
  (p95 11.7 px at 6 Hz against 3.8 px overall); this mixes the filter's edge effect with the real state of the data at the end of a run (runs often end at a loss or after
  a glitch), so the plan separates the two with a known truth (M-QLT-05 C and D).

**What is not obvious, and why this plan asks questions:**

- **"6 Hz" at the cutoff halves the amplitude.** With `filtfilt` the response is squared. The plan keeps W6's number as the design frequency of the single pass and says what
  it means; P5.08 (ablation 4/6/8 Hz on the number of pauses and the hip amplitude) is where the value is judged, so this task does **not** tune it.
- **A run ends where a hole begins, not only at the end of the clip.** The 1 s margins of the segment protect the ends of the take, but a hole inside the segment ends a run
  there too, and the filter's start-up and ending transients are felt in the last and first rows of every run. The data are flagged (`filtered`) and the runs table gives the
  start and end of every run, so a metric can leave the edge rows out; whether to do that is P5's choice, with M-QLT-05 D in front of it.
- **A filtered value is not a measurement.** As in the earlier stages nothing is fabricated: the filter changes values it was given, in place, and the cells keep their reason and
  their `interpolated` flag (a bridged value that is filtered is still a bridged value).

**The rules** (every rule has a test sub-ID below):

1. **Runs.** For each joint, a run is a maximal sequence of rows in which the cell has a value (finite; observed or bridged). x and y are one cell: they are filtered together on the
   same run. A cell without a value ends a run and is never part of one, so nothing is filtered across it and no NaN is ever an input of the filter.
2. **Design.** `scipy.signal.butter(order, cutoff_hz, btype="low", fs=1 / step_s, output="sos")`, order 4 and cutoff 6.0 Hz (W6), applied forward and backward (`sosfiltfilt`: zero
   phase, the same method as `filtfilt` in its numerically stable second-order-sections form, as `io/audio_sync.py` does); the padding is the default of scipy (odd extension by
   `padlen`). The gain of the result at the cutoff is 0.5 and its -3 dB point is a little under it: the docstring says so.
3. **Which runs are filtered.** A run is filtered if it has **more than `padlen`** rows (16 for the default). A shorter run is **not filtered**: its cells keep their input values,
   `filtered` is False, the table says `too_short`. Nothing is made up for it and nothing is set to NaN.
4. **The cutoff above Nyquist.** If `cutoff_hz >= fs / 2` the filter cannot be designed: no run is filtered, every run says `above_nyquist`, cells keep their input values and
   `filtered` is False. The cutoff is not clamped (that would be a number nobody chose).
5. **Fewer than two rows or a step that is not a number.** `step_s` NaN (zero or one row) means no run can reach `padlen` rows: nothing is filtered; a `step_s` that is not NaN, not finite or not above 0 is refused.
6. **Everything else is carried.** `reason` and `interpolated` are copied cell by cell: a bridged cell stays bridged (and filtered if its run is), a cell without a value keeps its reason,
   a cell built on a `mixed` row is data like any other. The result obeys the contract of the gap layer.
7. **Precision and dtype.** The filter runs in float64; the result has the input dtype. A filtered run is exactly what `sosfiltfilt` returns for that run alone.

**Unknowns, risks, questions** (the maintainer is asked; the proposed answer is applied if there is no other):

- **Q1. The cutoff and the order.** **Proposed: W6's order 4 and 6.0 Hz as the defaults, not tuned here.** The numbers of M-QLT-05 for 4, 6 and 8 Hz are reported so that P5.08 starts from them.
  The point to know: with `filtfilt` the gain at 6 Hz is 0.5, and at lesson frame rates the filter removes about a third of white noise and about two thirds of the second-difference jitter (the probe: 0.32).
  Alternative: pick 8 Hz now (a milder filter: jitter 0.51, p99 speed 0.84); not proposed, because the pause metric is what decides it and that is P5.08.
- **Q2. What a run that is too short becomes.** **Proposed: it keeps its input values, flagged `filtered = False`** (outcome `too_short`). On D20 that is 231 cells in 2.25 million. Alternatives: NaN (it loses
  observed or bridged values for a smoothing step that could not run), or filter anyway with a smaller padding (an edge-dominated result nobody asked for).
- **Q3. A clip whose Nyquist is under the cutoff** (10 fps or less; 12 fps exactly is also refused). **Proposed: nothing is filtered, flagged `above_nyquist`, no clamping.** Alternative: clamp the cutoff to
  0.9 of Nyquist (a number nobody chose, and the same clip would then be smoothed more or less depending on its frame rate).
- **Q4. `sosfiltfilt` or `filtfilt`.** **Proposed: `sosfiltfilt`** (the same forward-backward method in second-order sections, stable for any cutoff and rate, the precedent of `io/audio_sync.py`), with the
  default padding. W6 names `filtfilt`; the numbers are the same method with the better conditioning.
- **Q5. Which cells are filtered.** **Proposed: every usable cell of a long enough run, bridged cells and cells of `mixed` rows included, flags kept.** Alternative: leave the bridged cells out of the runs
  (every bridge would split a run: on D20 the 219 bridged gaps would each cut one) — rejected, a bridge is a short, linear piece and the filter treats it as data.
- **Risk: edges of runs.** See above; it is measured, reported and left to P5; the runs table gives the first and last row of every run.
- **Risk: a glitch that Hampel missed is smeared** (a step rings by 8 % on both sides): the order of the stages is DEC-0046 (Hampel first); M-QLT-05 D includes a spike that Hampel removes and one it does not.
- **Risk: smoothing of fast real movement and of the pauses of SYN-05.** The filter lowers the p99 speed by 23 % on the D20 runs (partly the noise it removes); M-QLT-05 C measures the speed in a pause and the
  error against the truth on SYN-05, which is what P5.07 will see.
- **Risk: cost.** One call of `sosfiltfilt` per run of 16 rows or more (965 runs for 22 chunks, a few seconds at most for an hour of video); the runs are found with array operations, not per cell.

## 2. Plan

**Design:**

```python
# quality/filters.py (Hampel is above)
RUN_OUTCOME_NAMES: Final = ("filtered", "too_short", "above_nyquist")   # the index is the code
RUN_FILTERED, RUN_TOO_SHORT, RUN_ABOVE_NYQUIST = 0, 1, 2

@dataclass(frozen=True)
class ButterworthParams:
    cutoff_hz: float = 6.0        # > 0, finite: the design frequency of the single pass
    order: int = 4                # 1 to 10
    padlen: int | None = None     # None: the default of scipy for the design (15 at order 4); else >= 0

@dataclass(frozen=True, eq=False)
class RunTable: joint, start, end, n, outcome        # one row per run, ordered by joint then first row

@dataclass(frozen=True, eq=False)
class FilterResult: keypoints, filtered, reason, interpolated, runs, params, sampling_hz

def lowpass_layer(keypoints, reason, interpolated, step_s, params=None) -> FilterResult
def lowpass_grid(layer: GridLayer, params=None) -> FilterResult        # step_s = layer.gridmap.step_s
```

Data flow: `check_gap_layer` (shapes, dtypes, the contract) → check `step_s` → `sampling_hz = 1 / step_s` (NaN if there is none) → design the SOS once and read its `padlen` (`None`
means scipy's default from the design) or give `above_nyquist` if `cutoff_hz >= fs / 2` → for each joint find the runs of finite cells with `np.diff` on the padded mask (vectorised) → the run table →
for each run with `n > padlen` one `sosfiltfilt` on the `(n, 2)` slice in float64, written into a copy of the input; other runs keep their values → flags, reasons and `interpolated` copied → read-only
result. No loop over cells; the slow oracle of the tests is the loop.
