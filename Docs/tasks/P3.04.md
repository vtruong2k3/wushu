## 1. Analysis

**Goal:** from the raw pose of a segment (`PoseRaw`) say **which person is the performer**, on one frame, in a way the tracking of P3.05 can start from and the UI of P8 can show, confirm or override. The rule of the plan: by default the
**largest box near the centre**; the user may point at a box instead. Nothing is tracked here (P3.05), and nothing is written to disk (the user's choice is part of the run request and the cache key: P7).

**What the plan, workflow and code say (read 2026-11-16):**

- Plan row P3.04 and T-TRK-01: "default choice: the largest box near the centre; a given box follows that person". W5 step 1: on the first frame of the segment (or a frame the user picks) show the boxes of the detected people; the user chooses; the default is the largest box
  near the centre. W5 step 3 later needs "do not jump to another person": the start must therefore be unambiguous or flagged.
- `PoseRaw` (P3.02/P3.03): compressed rows (`person_offsets`), `bboxes` (D, 4) xyxy [px], `keypoints`, `scores`, `t_sec`, `frame_index`, `segment_s`, `image_size`, `params` (including `min_score` and `min_valid_keypoints`). The frames cover the segment widened by 1 s; the
  segment's own first frame is the first one with `t_sec >= segment_s[0]`. Persons the model returned with few valid keypoints are stored (the maintainer's decision for the raw layer): the choice of the performer must not pick such a ghost by default.
- `tests/helpers/synth.py` `make_scene("SYN-12")`: target, distractor and bystander in 1920 x 1080 with the true identity of each slot (`truth["person_id"]`): usable to build a `PoseRaw` with known identities. `track/` exists but is empty.
- The real clip (D20 video 2) has frames with one person and frames with two (a presenter in the middle and a smaller person behind): a real check for the default rule, with the images viewed as in P3.01.

**In scope:** `track/target.py`: `select_target(raw, *, bbox=None, at_t_sec=None, params=None) -> TargetSelection`, `TargetParams`, `TargetSelection`, `TargetSelectionError`; tests; a helper that turns a `SynthScene` into a `PoseRaw`;
README, plan rows, tracking. **Out of scope:** following the person from frame to frame (P3.05), the lost-target state (P3.06), saving the choice (P7), the UI that draws the boxes and sends the box (P8), choosing by a click point.

**Inputs / outputs / units:** input `PoseRaw` (pixels, y down, `image_size` (width, height)); an optional user box `(x0, y0, x1, y1)` in the same pixels; an optional time `at_t_sec` [s from the stream start] of the frame the user looked at.
Output `TargetSelection` (frozen): `frame_pos` (index into the frames of `PoseRaw`), `frame_index` (row of the file's table), `t_sec`, `person_row` (row in the person arrays of `PoseRaw`), `bbox` (4 floats, the chosen person's box), `method` (`"default"` or `"user_box"`),
`score` (the default score of the chosen person, or the IoU with the user box), `n_candidates`, `ambiguous` (bool), `runner_up_ratio` (second best score / best score, or `None`), `offset_from_start_s` (frame time minus segment start [s]), `weak` (bool) and `n_valid_keypoints` (int) of the chosen person.

**The default rule (provisional values, recorded with their reason, not universal thresholds):**

1. *Frame*: the first frame at or after the segment start that has at least one eligible person, searched for up to `search_s` (2.0 s) from the start; a user time `at_t_sec` fixes the frame instead (no search). No eligible person there: `TargetSelectionError`
   (a message that says which frame and why); the target is never invented and the search never goes before the segment start.
2. *Eligible*: a person with at least `raw.params.min_valid_keypoints` keypoints of score at least `raw.params.min_score` (the same rule that decides who the runner follows) and a box of positive area with finite values.
3. *Score*: `area_share x centrality`, where `area_share = box area / image area` and `centrality = 1 - min(1, d / (0.5 x diagonal))`, `d` the distance of the box centre to the image centre. The person with the highest score is chosen; equal scores: the lowest person row (deterministic).
4. *Ambiguity*: `runner_up_ratio = second score / best score`; `ambiguous = runner_up_ratio >= 0.6` (confirmed change: a wrong silent choice costs more than one extra click): two people of similar size and place, so the UI must ask instead of trusting the default. A single eligible person is not ambiguous (`runner_up_ratio = None`).

**The user rule:** the person whose box has the largest IoU with the given box on the chosen frame, if that IoU is at least `min_iou` (0.3) and the guard of Q5, among **all** persons of the frame (a user may point at a weak one; it is flagged by a low score in the result, not refused); otherwise `TargetSelectionError`
(never the "closest" wrong person). A box with non-finite values or no area is refused.

**Constraints that apply:** AGENTS.md 5.1 (no invented person: an empty frame is an error, not a guess), 5.3 (the raw layer is not modified), 5.5 (provisional parameters are named with their reason; no universal threshold claimed), 6 (units and coordinates in docstrings; no `print`; IDs in logs),
9.4 point 7 (no dataset content in the repository).

**Unknowns, risks:**

1. *"Largest near the centre" can pick a bystander who stands close to the camera* (large) over the performer (smaller, central): the product score softens it, `ambiguous` flags close calls, and the user can always point. The weights are provisional until P3.07/P3.08 show real failures.
2. *A performer who enters after the start* (no one at the start frame): the search forward up to 2 s helps; later entries need the user to pick a frame.
3. *The first frame can have a weak or missed detection*: a ghost is not eligible by default; a performer with a bad first frame is found a few frames later (within `search_s`).
4. *Two performers* (a pair or group form): the default picks one and flags `ambiguous`; group forms are outside the MVP (one person).
5. *The tracker starts at `frame_pos`*, which can be after the segment start: P3.05 decides whether to track backwards to the start; recorded here for P3.05.

**Questions for the maintainer (the plan proceeds with the default if there is no answer):**

| # | Question | Default |
| - | -------- | ------- |
| Q1 | The default score | `area_share x centrality` (smooth), not a hard central region |
| Q2 | Ambiguity limit | **changed (confirmed): `runner_up_ratio >= 0.6`** marks `ambiguous` (the UI asks); provisional; the ratios of the first real clips are noted to tune it |
| Q3 | Frame when nobody is eligible at the segment start | search forward up to `search_s` = 2.0 s, then error; **plus the field `offset_from_start_s`** (frame time minus segment start) so that the UI can say "chosen at +0.7 s" |

| Q6 | Choose by a click point inside a box | not now (P8 sends a box) |
| Q7 | Where the choice is saved | not here: the run request and cache key (P7) carry `bbox` and `at_t_sec`; **notes for P7 (confirmed):** `pose_raw.npz` does not depend on the target, so changing the person recomputes only the tracking and what follows; the `TargetSelection` (method, frame, box, `ambiguous`, `weak`) goes into `run_manifest.json` |

## 2. Plan

**Design:** `track/target.py` (about 150 lines), pure numpy, no I/O. `TargetParams` (frozen, validated): `search_s = 2.0`, `min_iou = 0.3`, `ambiguity_ratio = 0.6`, `two_people_iou_ratio = 1.5`. Helpers: `_frame_persons(raw, frame_pos)` (row range from `person_offsets`), `_eligible(raw, rows)` (valid keypoints rule, finite box with area),
`_default_score(raw, rows)`, `_iou(boxes, box)`. `select_target` picks the frame (first frame with `t_sec >= segment_s[0] - 1e-9`, or the frame whose `t_sec` is within half a frame interval of `at_t_sec`, else error), applies the rule and builds `TargetSelection`.
Logging: `log.info` with the recording ID, the frame and the method only.
