## 1. Analysis

**Goal:** the second step of the quality layer (W6). The mask layer of P4.01 has holes: joints that are NaN, each with a
reason. P4.02 looks at each joint over time and, where the hole is **short** (at most 150 ms of real time) and has an
observed value on **both** sides, fills it with a straight line in time and marks every filled cell `interpolated`.
Longer holes stay NaN. Nothing is held, repeated, extrapolated or set to zero (AGENTS.md 5.1: no fabricated
observations; a short bridge is allowed only when it is flagged), the mask layer that is read is never changed (5.3),
and timestamps are the real PTS (5.2): the 150 ms is measured in seconds, never in frames.

**In scope:**

- `taiji_ai/src/taiji_ai/quality/gaps.py`: `GapParams`, `GapResult`, `GapTable`, `interpolate_gaps` (arrays) and
  `interpolate_track` (a thin wrapper over a `MaskedTrack` of P4.01); outcome codes and names.
- Tests T-QLT-03, T-QLT-04, T-QLT-05 on constructed arrays, a property test, SYN-06 (made for this task) and the chain
  `resolve` → `mask_track` → `interpolate_track`; a mutation check.
- A look at real footage (M-QLT-02) on files that already exist (the D20 pose pass of P3.08): how many gaps there are
  and what happens to them, and a **leave-gap-out check** of the error of a 150 ms bridge on real movement (observed
  values are hidden, bridged, and compared with what was observed). Numbers only; nothing committed.
- Records: W6 note in `TECH_WORKFLOW_V1.md`, the test rows and the definition in the plan, README, DEC-0045,
  CHANGELOG, TASK_STATUS.

**Out of scope:** Hampel (P4.03), VFR resampling (P4.04), Butterworth (P4.05), the left/right swap flag (P4.06; P4.02
only gives it a place to act, see Q2), coverage and `quality.json` (P4.07), the UMONS test (P4.08), a **file format** for
the layers (X.29; the `interpolated` flag is one of the columns it will have to store), a change of the 150 ms (it is
the W6 value; the leave-gap-out numbers *evaluate* it, a change would be a decision with the maintainer, as for
`tau_kp` in DEC-0042), any use of a score for an interpolated value (there is none: the model never saw it).

**Inputs / outputs / interfaces:**

| | |
|---|---|
| `keypoints` | `(T, 26, 2)` float32 or float64, pixels of the upright image, x right, y down; **NaN exactly where `reason != ok`** |
| `reason` | `(T, 26)` uint8, the codes of `quality/mask.py` (`ok`, `low_conf`, `non_finite`, `not_tracked`, `frame_invalid`); later tasks may add codes (for example Hampel's `outlier`) |
| `t_sec` | `(T,)` float64, seconds from the stream start, real PTS: finite and strictly increasing |
| `blocked` (optional) | `(T, 26)` bool: cells that must not be bridged and must not be used as an anchor of a bridge (Q2) |
| `params` | `GapParams(max_gap_s = 0.150, never_fill = (NOT_TRACKED,))` |
| result | `GapResult`: `keypoints` (the observed values, the interpolated values, NaN elsewhere; the input dtype), `interpolated` `(T, 26)` bool, `observed` `(T, 26)` bool (`reason == ok`), `reason` (the mask's, **unchanged**: why the cell was missing, also for a filled cell, so that P4.07 can report coverage by reason), `gaps` (`GapTable`), `params`; property `usable = observed or interpolated`. Every array is new and read-only |
| `GapTable` | one row per **gap** = a maximal run of unobserved frames of one joint: `joint` int16, `start` and `end` int32 (first and last frame row, inclusive), `missing_s` float64 (frames x median frame interval, NaN if `T < 2`), `bridge_s` float64 (`t[end+1] - t[start-1]`, **NaN when open**), `outcome` uint8 with `OUTCOME_NAMES = ("filled", "too_long", "never_fill", "blocked", "open_start", "open_end", "open_both")` |

**The rule, in order, for one gap (a run of unobserved frames of one joint):**

1. **Open**: no observed frame before it (`open_start`), none after it (`open_end`), or neither (`open_both`, a joint that
   is never observed): not bridged. This is extrapolation, not interpolation.
2. **Never fill**: any cell of the gap has a reason in `never_fill` (default `not_tracked`: the frame is not the
   target's, the tracker lost them or had not found them yet): not bridged (`never_fill`; the cause of the hole stays in `reason`). Identity is the first
   thing the tracker can get wrong; a line drawn across an absence would join two possibly different people.
3. **Blocked**: a cell of the gap or one of the two anchors is `blocked`: not bridged (`blocked`).
4. **Length**: `bridge_s = t[end+1] - t[start-1]`; bridged only if `bridge_s <= max_gap_s + 1e-9` s (`filled`);
   otherwise `too_long`.
5. A bridged gap gets `x(t) = x_before + w (x_after - x_before)`, `w = (t - t_before) / (t_after - t_before)`, for x and y
   separately, with the **real** times. The anchors are always `ok` cells. The value is computed in float64 and
   stored in the input dtype.

The first rule that applies names the outcome (open, then not tracked, then blocked, then too long), so a refused gap
has one cause in the table; the cause of the hole itself stays in `reason`.

**Unknowns, risks, questions** (the maintainer is asked; the proposed answer is applied if there is no other):

- **Q1. What is the length of a gap?** The generator of the scenes reports two (P0.07, D2): the *missing span*
  (`n_missing x dt`) and the *bridged span* (`t[after] - t[before]`). They differ by one frame interval: at 30 fps, 4
  missing frames are 133 ms against 167 ms. **Proposed: the bridged span**, because it is the time during which the joint
  was not seen (we know where it was at `t_before` and at `t_after`, and a straight line replaces what happened in
  between), it needs no estimate of the frame interval, and it is what P0.07 recommended. Consequence: at 30 fps up to 3
  missing frames are bridged (bridge 133 ms), 4 are not (167 ms); at 60 fps up to 8 (150 ms); at 25 fps up to 2 (120 ms; 3
  would be 160 ms). The alternative (missing span) bridges one frame more at every rate and reads closer to "150 ms of
  missing frames", but then the bridge itself is longer than 150 ms.
- **Q2. "Do not bridge across a suspected turning point" (the last words of the W6 row).** A suspected turning point can be
  a reversal of motion or a left/right swap. Detecting either well is a task of its own (P4.06 detects "L/R pairs that jump
  across at the same time"), and a rule invented here would need a speed threshold that nobody has measured (a still
  person flips the sign of the velocity at random). **Proposed:** `interpolate_gaps` takes an optional `blocked` mask
  (cells that are not bridged and not used as anchors); P4.02 does not detect anything itself; P4.06 produces the mask
  and P4.07 wires the two. The W6 sentence is then met by the interface, and its detector is P4.06's. The alternative
  (a built-in guard now) costs a threshold and a risk of refusing bridges at rest.
- **Q3. Which holes may be bridged?** Proposed: `low_conf`, `non_finite` and `frame_invalid` yes (a short run of them has
  observed frames on both sides: it is a short gap like any other, and every cell is flagged); `not_tracked` **never**
  (rule 2), also when it lasts 100 ms. A bridged `frame_invalid` frame is a skeleton built only from its neighbours, which
  is why every cell keeps its `reason` and its `interpolated` flag. The alternative (never bridge `frame_invalid`) is
  stricter and leaves one-frame holes in the continuous stretches that P4.05 needs.
- **Q4. Real-footage check (M-QLT-02):** yes, as a measurement only; the 150 ms and everything else stay as W6 says. If
  the leave-gap-out numbers look bad the report says so and the maintainer decides (as DEC-0042 did for `tau_kp`).
- **Risk: float time at the boundary.** `t_sec` is a product of PTS and a time base, so 0.15 s can come out as
  0.15000000000000002. The comparison carries 1e-9 s (the same device as the epsilon of P4.01) and tests sit on both
  sides of it.
- **Risk: order with Hampel.** W6 lists the Hampel filter (P4.03) after the gaps and says it sets NaN "before the
  filter". If Hampel runs first its holes can be bridged; if after, they cannot. `interpolate_gaps` works on any layer with
  NaN and a reason, and a new reason code is bridgeable unless it is in `never_fill`, so either order works; the order is
  decided in P4.03 and P4.07, not here.
- **Risk: a bridge is only as good as its anchors.** If an anchor is a wrong joint (a swap, a joint off by 50 px with a
  score of 0.8: P3.08 found such cases and no score warns), the line joins wrong values and the cell is flagged
  `interpolated` but wrong. The flag says "not observed", not "right". `blocked` is the hook for the suspects.
- **Risk: cost.** Per joint a loop over the gaps (Python) on up to 157 000 frames x 26 joints; the gaps are few (the mask
  removes 0.00 to 0.18 % of the cells), so it is cheap; the property test keeps `T` small.

## 2. Plan

**Design:**

```python
# quality/gaps.py
MAX_GAP_S: Final = 0.150          # W6
OUTCOME_NAMES: Final = ("filled", "too_long", "never_fill", "blocked", "open_start", "open_end", "open_both")

@dataclass(frozen=True)
class GapParams:
    max_gap_s: float = MAX_GAP_S                   # finite, > 0; bool and str refused
    never_fill: tuple[int, ...] = (NOT_TRACKED,)   # reason codes (0..255) whose cells are never bridged

def interpolate_gaps(keypoints, reason, t_sec, params=None, blocked=None) -> GapResult: ...
def interpolate_track(masked: MaskedTrack, params=None, blocked=None) -> GapResult: ...
```

Data flow: validate (shapes, dtypes, `t_sec` finite and strictly increasing, `reason` consistent with the NaN pattern:
a finite cell with `reason != ok` or a NaN cell with `reason == ok` raises `QualityError` naming the first row and
joint by index only) → for each joint find the runs of `reason != ok` (vectorised edges, one Python loop over the runs)
→ apply the rule of section 1 → write the table → fill the bridged runs from their two anchors → freeze the arrays.
`interpolate_track` passes `masked.mask.keypoints`, `masked.mask.reason` and `masked.t_sec`; the margins of the segment stay,
the timeline stays with the caller's `MaskedTrack`. The `GapTable` is built from lists and turned into arrays once.
