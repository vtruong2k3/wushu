## 1. Analysis

### 1.1 Goal

One call that compares a query segment with a reference segment the way W8 says: features of both (P6.01), the masked
cost (P6.02), constrained DTW (P6.03a), and an `Alignment` that holds everything a later step needs (the path, `D`, the
cost, the features, the settings). And the plan's acceptance of P6 on the generator: a sequence stretched in time keeps
its shape (`D ≤ 0.02` trunk lengths, SYN-10), and another movement is clearly farther than a variant of the same one
(`D(ref, other) ≥ 2 D(ref, variant)`, SYN-11).

### 1.2 Facts read (2026-11-17)

- Plan: T-CMP-04 "SYN-10: shape about 0 when stretched; the path respects the band"; tolerance table: SYN-10 `D ≤ 0.02`
  (trunk lengths, noise-free), SYN-11 `D(ref, other) ≥ 2 × D(ref, variant)`; acceptance of P6: "an identical sequence
  gives distance 0; a sequence stretched in time gives the same shape and the right speed ratio; another action is
  refused; on UMONS the same class is closer than another class for most classes".
- SYN-10 (default `k_start` 0.8, `k_end` 1.25, 4 s): the query is the reference re-timed; `t_ref_of_query`, `rate_k` are
  the truth. SYN-11: the reference (`raise_lower`), another action (`open_close`) and a variant (small warp and noise).
- The layers of the generator go through the real chain (`helpers/metric_layers.layer_of_sequence`).

### 1.3 Scope

**In:** `compare/align.py`: `Alignment` and `align(reference, query, *, min_visible, band, step="symmetricP1",
weights=None)`; unit tests; golden tests T-CMP-04 (SYN-10) and the SYN-11 ratio, and T-CMP-03 through the whole chain;
mutation check; docs. **Out:** tempo and deviation (P6.04), guards (P6.05: `align` does not check action or view; the
caller asks the guard first), the band (P6.06), a file on disk.

### 1.4 Interface

```python
@dataclass(frozen=True, eq=False)
class Alignment:
    reference: FrameFeatures; query: FrameFeatures
    cost: CostMatrix; result: DtwResult
    settings: Mapping[str, object]   # read-only, NON-EMPTY, short-code names, plain values: feature_version, units,
                                     #   weights, min_visible, band, step, min_scale_s, min_segment_length (the last two
                                     #   are the features' echoes and MUST be equal in the two feature sets, else align
                                     #   refuses: a reference and a query made with different minimums are not compared)
    @property
    def distance(self) -> float | None: ...   # result.distance
    def as_comparison(self, reference_id: str, query_id: str) -> Comparison: ...  # P6.06's type: the two segment IDs
                                                      #   (short codes), D, settings; align.py imports it, not the reverse
    def matched_query_times(self) -> np.ndarray: ...  # (m,) float64 s: per reference row, the mean query time of the
                                                      #   path cells on it; NaN for every row when there is no path

def align(reference: FrameFeatures, query: FrameFeatures, *, min_visible: int, band: float,
          step: str = "symmetricP1", weights: Mapping[str, float] | None = None) -> Alignment
```

## 3. Plan re-read (before coding)

Plan re-read: 2026-11-17 — OK, with the following checks and clarifications (no change of design; none of the finished
modules is edited).

- **Checked against the code of the finished modules.** `cost_matrix(reference, query, *, min_visible, weights=None,
  block_rows=...)` gives a `CostMatrix` with axis 0 the query and axis 1 the reference, `weights` as a tuple of floats
  (one per unit, in the units' order), `min_visible` as an `int`, `units` as the names, `feature_version`. `dtw(cost, *,
  band, step)` accepts a `CostMatrix` through `.values`, returns `DtwResult` (`path (L, 2)` int64 as `(query row,
  reference row)` including the middle cells of compound steps, `distance` = `D`, the plain mean of the cost over the
  listed cells; `normalised` is not `D`; `params` has `band` as a float) and returns `no_path` with an empty `(0, 2)` path
  and `None` numbers (a result, not an error). `FrameFeatures` carries the two echoes `min_scale_s` and
  `min_segment_length` (`None` or a float), `t_sec (N,)` (not validated by the cost), `version` and `units`. The cost
  checks the units and the version of the two feature sets, `min_visible` and the weights; it does **not** check the
  echoes nor `t_sec`.
- **`Comparison` does not check the IDs itself.** The brief for this task says the IDs are "checked by `Comparison`
  itself"; the code of `compare/reference_band.py` shows a plain frozen dataclass with no `__post_init__`: the short-code
  check of the two IDs (and the refusal of a segment compared with itself) is made later, inside `reference_band()`
  (`_check_comparison`). The plan of this task (T-CMP-03l) already says that `as_comparison` refuses an ID that is not a
  short code, so `align.py` checks the two IDs itself with the same pattern (`[A-Za-z0-9_.-]{1,64}`) and a test pins the
  parity with `reference_band` (an ID that one accepts the other accepts). `reference_band.py` is not edited and
  `align.py` imports only `Comparison` from it. `as_comparison` does **not** refuse equal IDs: a segment compared with
  itself is legitimate for T-CMP-03; the band's own rule refuses it where it matters.
- **Settings values: `None` is a plain value.** The overview lists "numbers, strings, tuples, mappings". `min_scale_s`
  and `min_segment_length` are `None` when no minimum was applied (the features' own convention). I keep `None` (JSON
  null, equal to itself in `reference_band._equal`) and do **not** invent a sentinel number or string, which would be a
  fabricated value. The coordinator may add "or `None`" to overview §3.4.
- **What `align` validates beyond the parts.** (1) The two arguments are `FrameFeatures`. (2) The two echoes are `None` or
  a finite number (not a bool) and equal in the two sets, else `CompareError` naming the setting. (3) `t_sec` of each
  feature set is a one-dimensional finite strictly increasing float array with one entry per row of `values` (the cost
  does not read it, `matched_query_times` and P6.04 do: a clock that is not a clock is refused where it enters, AGENTS.md
  5.2). The checks of units, version, `min_visible`, weights, band and step are the parts' own and pass through with
  their messages. A bad band or step is found by `dtw`, after the cost was computed (about 0.3 s at 900 x 900), which is
  accepted to keep `align` exactly `dtw(cost_matrix(...))` without a second copy of the rules.
- **Settings.** Exactly the eight names of the plan: `feature_version`, `units` (tuple of names), `weights` (tuple of
  floats as the cost echoes them), `min_visible` (int), `band` (float), `step`, `min_scale_s`, `min_segment_length`; a
  read-only `MappingProxyType` over a private dict; every value a plain Python object (no numpy scalar). `roll_deg`
  and the lengths `n`, `m` are **not** settings of the comparison (a camera roll is taken out of each segment separately,
  and the lengths are not a rule that changes `D`).
- **Test settings (Q1) fixed:** `min_visible` 11 of 21 units (half, rounded up), `band` 0.2, `symmetricP1`, weights 1.
  SYN-10 is generated with `scale_px=120` (the generator refuses `query_scale` 1.7 at 200).
