## 1. Analysis

### 1.1 Goal

Give every metric result the one thing that lets a report draw a conclusion: a **signed record** of the metric (v3 §8.2),
stored in SQLite, loaded by a function, and applied to a summary by a rule that can only make a result `conclusive` when the
record is signed, enabled and matches how the result was computed. Without such a record the result stays `experimental`:
it shows its numbers and `conclusive` is false (T-MET-11, AGENTS.md §5.5). The records themselves are written by the coach
in P10.06; this task builds the table, the rules and the loader, and writes no real record.

### 1.2 Facts read (2026-11-17)

- **Plan row P5.09:** "the `metric_record` table and a function that loads a record; a metric without a record is
  `experimental` and draws no conclusion"; output `metrics/records.py`; test T-MET-11 ("a metric without a signed
  `metric_record`: status `experimental`, the report concludes nothing"). Consumers: P8.10 (finding templates from metrics
  that qualify, depends on P5.09), P10.06 (choose hip A or B and sign a record per metric, T-MET-11), gate G03 ("every enabled
  metric has a signed record; error below the smallest useful change").
- **v3 §8.2:** each metric has a record of intended use, supported views, gold annotations, human variability, smallest
  useful change, measurement error, minimum valid duration and a signed threshold; the record is locked before the pilot
  holdout; if the error is as large as the change the coach wants to see, the measurement scope or the capture changes.
- **The table today** (`migrations/0001_init.sql`): key `(metric_name, version)`, `intended_use`, `supported_views` (JSON
  list), `human_variability`, `smallest_useful_change`, `measurement_error`, `min_valid_duration_s`, **one** `threshold REAL`,
  `status` (`experimental`, `enabled`, `retired`, default `experimental`), `signed_by`, `signed_at`. No code reads or writes it
  (searched `src/`), so it is empty in every database.
- **What the table cannot hold:** (1) a metric has several thresholds (`pause_tau` and `pause_min_s` of the speed metrics,
  P5.07) and a single `threshold` column cannot name them; (2) DEC-0061: `τ`, `d_min` and the Butterworth cut-off are **one
  triple**, the record must carry the cut-off; (3) the record applies to a version of the metric code, but its own key
  `version` must change when the coach signs new numbers for the same code (P5.01 made `record_version` "the version of the
  signed record", distinct from `metric_version`), so the table needs a `metric_version` column; (4) v3's "gold annotations"
  and the provenance of AGENTS.md §9.4.6 (`data_sources`: a record learned from a dataset inherits its restrictions) have no
  column; (5) the units of the numbers are not stated.
- **The summary side is ready** (`schemas/metric.py`, P5.01): `record_status` (the table's three values), `record_version`
  (exactly when `enabled`), `threshold_source` (`signed_record` needs `enabled`, `unsigned_config` needs `experimental`),
  `conclusive` = `sufficient` and `enabled`. Every metric calls `make_summary(..., record_status="experimental")` today, and
  the speed metrics label their pause outputs `unsigned_config` (`metrics/tempo.py`).
- **What each metric echoes in `parameters`** (the values a record must bind): `hip_height_a`: `min_reference_s`,
  `min_valid_s` (+ measured `scale_px`, `roll_deg`, ...); `hip_height_b`: `min_scale_s`, `min_valid_s`; `trunk_lean_lr`,
  `trunk_lean_fb`: `supported_views` (joined with `-`), `min_valid_s`; `speed_hands`, `speed_hips`, `speed_feet`:
  `min_valid_s`, `min_scale_s`, `pause_tau`, `pause_min_s`. **No metric echoes the cut-off**, although the layer knows it:
  `PoseFiltered.meta.params.filter.cutoff_hz`, and `meta.timeline.sampling_hz`; the filter is skipped when
  `cutoff_hz >= sampling_hz / 2` (`quality/filters.py`, the `above_nyquist` outcome; `quality.json` warns
  `filter_skipped_above_nyquist`).
- **Store conventions** (`store/db.py`, `store/participants.py`): numbered SQL migrations, one transaction each; a store
  module validates every field, writes the row and its `audit_log` row in one transaction, `actor` is a role code
  (`cli:A`, `cli:B`, `cli:O`, `cli:H`, up to two digits), messages and logs never echo free text.
- **Views:** the `segment` table allows `front`, `side`, `oblique`, `back`, `unknown`; the summaries carry `view_category`.

### 1.3 Scope

**In scope:**

1. Migration `0002_metric_record.sql`: the table rebuilt with the columns of §1.5 (Q2).
2. `MetricRecord`, the Pydantic model of a row, with the rules of a signed record (Q5).
3. A store module: save a record (with its audit row), retire one, load one, find the current record of a metric version;
   records are immutable once enabled (Q6).
4. `metrics/records.py`: the registry of the seven metrics (units, version, the parameters a record may bind, the threshold
   parameters) and `apply_record(summary, record)`, which returns the summary with its record status and the reason of the
   decision (Q8).
5. Every metric echoes the cut-off actually applied to its layer, `filter_cutoff_hz` (Q4).
6. Tests (T-MET-11 split into sub-IDs, T-STORE-08 for the migration), mutation check, docs.

**Out of scope:** any real record (P10.06, signed by H), a CLI or UI to sign (P10.06 / P8), the pipeline call (P7: load the
record, compute with its values, apply it), the report text (P8.10 reads `conclusive`), thresholds for a duration over an
angle (B2 asks for it only with a record; no such output exists yet), choosing hip A or B (P10.06).

### 1.4 Inputs, outputs, interfaces

```python
# schemas/metric_record.py
RecordView = Literal["front", "side", "oblique", "back"]   # "unknown" is never supported
class MetricRecord(FrozenModel):
    metric_name: str              # NAME_RE; one of the registry (checked by the store and by apply_record)
    version: str                  # VERSION_RE: the record's own version (the summary's record_version)
    metric_version: str           # VERSION_RE: the metric code it applies to (the summary's metric_version)
    units: Unit                   # the units of the numbers below = the metric's units
    status: Literal["experimental", "enabled", "retired"]
    intended_use: str             # the coach's sentence, 1..500 characters, one line; never logged, hashed in the audit
    supported_views: tuple[RecordView, ...]
    gold_reference: str | None    # short code of the gold annotations (a report or task ID), not a path
    human_variability: float | None      # >= 0, in units
    smallest_useful_change: float | None # > 0, in units
    measurement_error: float | None      # >= 0, in units
    min_valid_duration_s: float | None   # >= 0 [s]; binds the metric argument min_valid_s
    parameters: dict[str, ParamValue]    # the other values the metric must be computed with (bounded, as in MetricHeader)
    data_sources: tuple[DataSource, ...] # provenance of the numbers (AGENTS.md 9.4.6); empty = our own recordings
    signed_by: str | None         # role code of a coach, ^cli:H\d{0,2}$
    signed_at: date | None

# store/metric_records.py
class MetricRecordError(ValueError)
def save_record(conn, record: MetricRecord, *, actor: str, today: date | None = None) -> MetricRecord
def retire_record(conn, metric_name: str, version: str, *, signed_by: str, actor: str, today: date | None = None) -> MetricRecord
def load_record(conn, metric_name: str, version: str) -> MetricRecord | None
def current_record(conn, metric_name: str, metric_version: str) -> MetricRecord | None

# metrics/records.py
@dataclass(frozen=True)
class MetricSpec: name: str; units: Unit; version: str; bindable: frozenset[str]; thresholds: frozenset[str]
METRICS: Mapping[str, MetricSpec]          # the seven metrics
Decision = Literal["enabled", "no_record", "record_experimental", "retired",
                   "view_not_supported", "parameters_differ", "thresholds_not_signed"]
@dataclass(frozen=True)
class RecordedSummary: summary: MetricSummary; decision: Decision
def check_record(record: MetricRecord) -> None   # registry rules; MetricRecordError naming the field
def apply_record(summary: MetricSummary, record: MetricRecord | None) -> RecordedSummary
```

Units: the record's numbers are in the metric's units (`body_lengths` for hip height, `deg` for trunk lean,
`body_lengths_per_s` for the speeds), `min_valid_duration_s` in seconds, `filter_cutoff_hz` in hertz. No path, no person's
name, no free text in logs or messages (only IDs, codes and the decision).

### 1.5 Conventions fixed by this task

1. **Key.** `(metric_name, version)` stays the key; `version` is the **record's** version and `metric_version` the metric code
   it applies to (Q1). At most one `enabled` record per `(metric_name, metric_version)` (a partial unique index).
2. **The current record** of `(metric_name, metric_version)` is the enabled one if there is one, else the one with the highest
   `version` (a draft or a retired record). A draft of the next version never displaces an enabled record.
3. **A signed record** (`enabled`): every v3 field present (`intended_use`, `supported_views` not empty, `gold_reference`,
   `human_variability`, `smallest_useful_change`, `measurement_error`, `min_valid_duration_s`), `signed_by` a coach role code,
   `signed_at` a date not in the future, **`measurement_error < smallest_useful_change`** (G03, v3 §8.2), and
   `parameters` binds `filter_cutoff_hz` (DEC-0061: the error budget was measured on a layer filtered at one cut-off).
   `pause_tau` and `pause_min_s` are bound together or not at all (P5.07). An `experimental` record may be a draft (fields
   missing, unsigned) or a signed decision to keep the metric experimental (P10.06 "enable or keep experimental"); a
   `retired` record is signed (who retired it, when).
4. **Immutable once enabled.** An enabled or retired record is never changed: new numbers are a new `version`; an enabled
   record can only become `retired` (`retire_record`, audited). A draft (`experimental`) can be replaced while unsigned.
5. **`apply_record`** never changes a number. In this order: a record of another metric, metric version or units is a
   programming error (`MetricRecordError`); no record → `no_record`; a draft or signed experimental record →
   `record_experimental`; retired → `retired` (status `retired`; refused when the summary has a threshold output, which a
   retired metric cannot sign, Q7); the summary's view not in `supported_views` → `view_not_supported`; a bound value
   (`min_valid_duration_s` against `min_valid_s`, each key of `parameters`) missing or not exactly equal →
   `parameters_differ`; a threshold output whose threshold keys the record does not bind → `thresholds_not_signed`; else
   `enabled`: `record_status = "enabled"`, `record_version = record.version`, and `threshold_source` becomes `signed_record`
   if the summary has threshold outputs. Every decision other than `enabled` leaves the summary `experimental` (its numbers
   shown, `conclusive` false). Equality is exact: the pipeline passes the record's own values to the metric.
6. **The cut-off echo.** Every metric's `parameters` gets `filter_cutoff_hz`: the layer's `cutoff_hz` when it is below
   `sampling_hz / 2`, `None` when the filter was skipped (above Nyquist, or a layer of one row). Added once, in the shared
   assembly of `metrics/rows.py`; no value of any series or statistic changes; the metric versions stay `1` (an echo of a
   parameter that was always in force, not a change of definition).

### 1.6 Constraints that apply

AGENTS.md §5.5 (no universal threshold; a threshold only from a signed record, otherwise `experimental`), §5.12 (thresholds
need the coach: `signed_by` is an H role code), §5.1 (a decision never invents or hides a number: values are kept, the status
says what they are worth), §5.4 (units stated), §9.4.6 (`data_sources` on a derived artifact), §6 (Pydantic v2, no bare
`except`, logs with IDs only), §4.1 (a schema change updates `TECH_WORKFLOW_V1.md` §4.5 and a `DEC`).

## 2. Plan

### 2.1 Design

The record is data the coach signs; the metric code stays pure. The pipeline (P7) will do: `current_record(conn, name,
metric_version)` → compute the metric with the record's values (`min_valid_s`, `pause_tau`, ...) on a layer filtered at the
record's cut-off → `apply_record(summary, record)` → write the summary. This task provides every piece except that call.
`metrics/records.py` holds the registry of the seven metrics, built from the metric modules' own constants
(`UNITS`, `METRIC_VERSION`, `GROUP_METRIC_NAMES` of `tempo.py`, `METRIC_NAMES` of `trunk_lean.py`; the two hip height names
have no constant, so the test takes them from one run of each function), so the registry cannot drift (a test pins it).
