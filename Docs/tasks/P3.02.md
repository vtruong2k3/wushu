## 1. Analysis

**Goal:** from one recording and one time range (a segment) produce the **raw pose of everybody the models see**, frame by frame, with the real timestamp of every frame: the input of P3.03 (`pose_raw.npz`),
P3.04 to P3.06 (target choice and tracking) and everything after. Nothing is chosen, tracked or filtered here.

**What the plan, the workflow and the code say (read 2026-11-16):**

- Plan row P3.02 and tests T-POSE-05..07 (`IMPLEMENTATION_PLAN_V1.md` sections 7 and 15.4): read the frames by PTS in `[start - 1 s, end + 1 s]`; the detector runs every N frames; between two runs the box comes from the
  keypoints of the previous frame, widened by 10 to 15 %; when nobody is seen the detector runs at once.
- W4 (`TECH_WORKFLOW_V1.md`): original video, PyAV by PTS, margin of 1 s at both ends, keypoints in the pixels of the image **turned the right way** (display rotation), score and `t_sec`, no mirroring, `onnxruntime` with CUDA,
  the provider actually used goes to the run manifest; `pose_raw.npz` may be ragged or padded with `n_persons` (P3.03). Speed (`processing_seconds / video_seconds`) and VRAM are measured in P3.07.
- `pose/rtm.py` `PoseEstimator`: `detect(frame_bgr) -> (N, 4)` and `estimate(frame_bgr, bboxes) -> PoseResult(bboxes (N, 4), keypoints (N, 26, 2), scores (N, 26))` are separate calls (written for this task);
  `providers` and `model_fingerprint` exist. The GPU smoke test passes now (detector 30.6 ms, pose 5.2 ms per person at 1080p).
- `io/frames.py` `iter_frames(path, t0, t1, rotation_deg)` decodes by PTS (backward seek to a keyframe, frames before `t0` skipped) and can turn the picture; its `index` is the position **inside the decoded range**, not in the file.
- The recording folder holds `source<ext>`, `recording.json` (`display_rotation`, `n_frames`, `start_pts`, `time_base`, `median_dt_s`) and `pts.parquet` (`frame_index`, `pts`, `t_sec`): the frame index of the file is the row of the table.
- Fixtures that exist (`tests/conftest.py`): `cfr_video`, `vfr_video`, `rotated_video`, `offset_video`, `dropped_frame_video`, `one_frame_video`, `hd_video_1080p`; helper `tamper_pts`. None has a person: the real models see nobody in them.
- D20 (registry, DEC-0036) has real people (a presenter); local only, never in git.

**In scope:** `pose/runner.py` (`run_pose`, `PoseRunParams`, `PoseRaw`, `PoseRunStats`, `PoseRunError`, `box_from_keypoints`); a `Protocol` so that tests run with a scripted fake model (CPU, no GPU); the tests below;
README and tracking. **Out of scope:** saving `pose_raw.npz` (P3.03), choosing and following the target (P3.04 to P3.06), quality masks (P4), the worker, the GPU job lock and the run manifest (P7), the speed and VRAM numbers (P3.07),
the choice of N (P3.07 measures N = 1, 5, 10; here N is a parameter with a default).

**Inputs / outputs / interfaces:**

```python
class PoseModel(Protocol):                      # PoseEstimator satisfies it; tests use a fake
    providers: dict[str, str]; model_fingerprint: dict[str, str]   # name -> sha256, as ModelRegistry.fingerprint()
    def detect(self, frame_bgr: np.ndarray) -> np.ndarray: ...                     # (N, 4) xyxy px
    def estimate(self, frame_bgr: np.ndarray, bboxes: np.ndarray) -> PoseResult: ...

@dataclass(frozen=True)
class PoseRunParams:
    detect_every_n: int = 5        # detector runs on the first frame and every N frames; N >= 1
    bbox_margin: float = 0.12      # widening of the box taken from keypoints, share of its width and height (plan: 10 to 15 %)
    min_score: float = 0.3         # a keypoint under this score is not used to build a box
    min_valid_keypoints: int = 6   # a person with fewer valid keypoints is lost (no box for the next frame)
    segment_margin_s: float = 1.0  # frames read before the start and after the end (W4)

def run_pose(recording_dir: Path, start_s: float, end_s: float, model: PoseModel, *, params: PoseRunParams | None = None) -> PoseRaw
```

`PoseRaw` (frozen dataclass of numpy arrays; **ragged as compressed rows**, the form P3.03 will store, since W4 allows ragged or padded):

| Field | Shape / type | Meaning |
| ----- | ------------ | ------- |
| `frame_index` | (F,) int32 | row of the frame in `pts.parquet` (the file's frame index, not the index inside the window) |
| `t_sec` | (F,) float64 | seconds from the stream start, real PTS, strictly increasing |
| `person_offsets` | (F + 1,) int64 | persons of frame `i` are rows `person_offsets[i]:person_offsets[i + 1]` of the arrays below (`n_persons = diff`) |
| `bboxes` | (D, 4) float32 | xyxy, image pixels |
| `keypoints` | (D, 26, 2) float32 | x, y in pixels of the upright image (display rotation applied), y down; **never NaN-filled or clamped**: what the model returned |
| `scores` | (D, 26) float32 | the model's scores |
| `from_detector` | (D,) bool | the box of this person came from the detector (true) or from the previous keypoints (false) |
| `image_size` | (W, H) ints | of the upright image the coordinates refer to |
| `display_rotation` | int | degrees, from the manifest |
| `segment_s` | (start, end) floats | the segment asked for; the frames cover `[start - segment_margin_s, end + segment_margin_s]` clipped to the recording |
| `params`, `model_fingerprint`, `providers` | | what produced it (for the run manifest of P7) |

`PoseRunStats` (separate, not part of the equality of two runs): `n_frames`, `n_detector_calls`, `n_pose_calls`, `n_persons_total`, `elapsed_s` (wall clock; P3.07 turns it into the real-time factor).
A segment with no person in a frame is a frame with `n_persons = 0`, never a frame with invented zeros (AGENTS.md section 5.1).

**Algorithm (per decoded frame, in presentation order; state: the persons found on the previous frame and the frames since the last detector run):**

1. `run_detector` is true when there is no followed person, or `frames_since_detector + 1 >= N` (`frames_since_detector` is 0 on a detector frame, so N = 5 gives detector frames 0, 5, 10); otherwise the boxes are `box_from_keypoints` of each previous person (same order).
2. If the boxes are empty (nobody to follow) the detector runs on this frame (`frames_since_detector = 0`).
3. `estimate(frame, boxes)`. **Every person the model returns is stored**, also one with few valid keypoints (Q6: the raw layer keeps what the model saw). A person is *followed* (gets a box for the next frame) only if it has at least `min_valid_keypoints` keypoints of score >= `min_score`.
4. If this was a derived-box frame and no person is followed (all weak, or none), the detector runs now on this same frame and the estimate is repeated; **the result of the repeat replaces the derived-box result** (all persons of a stored frame come from one pass): a frame is never lost to a stale box.
5. The persons are stored (with `from_detector`); the followed ones become the previous persons (when there are none, the next frame runs the detector). A person who enters between two detector runs is picked up at the next detector run (at most N - 1 frames later: 0.17 s at 30 fps and N = 5).

`box_from_keypoints(kp, scores, image_size, margin, min_score, min_valid)`: the box of the valid keypoints, widened by `margin` of its width and height on each side, clipped to the image; `None` when fewer than `min_valid` are valid (NaN and
infinite values are not valid).

**Errors, raised and never swallowed (`PoseRunError`, AGENTS.md section 6):** `start_s >= end_s` or a segment that does not overlap the recording; a missing or unreadable manifest or table; the frames decoded in the window are not the rows of the table
(count or PTS differ: the file changed since the ingest, or a frame could not be decoded); the model raises on a frame (the frame index is in the message, the cause is chained, no partial result is returned). Logs carry the `recording_id`
and counts only.

**Constraints that apply (AGENTS.md):** 5.1 no made-up observations; 5.2 real PTS (the table, never fps); 5.3 raw pose is its own layer (nothing filtered here); 5.6 models only from the verified registry (the estimator is given, already verified);
5.7 heavy work only in the worker subprocess and one GPU job at a time: `run_pose` is a library function, the **caller** (P7 worker) owns the process and the lock, the FastAPI process never calls it; 6 type hints, units and coordinates in docstrings,
no `print` in `src/`; 9.4 point 7 no dataset content in the repository (the test on D20 is skipped when the file is absent and stores no frame, no keypoint file).

**Unknowns, risks:**

1. *Box from keypoints is smaller than the person when the arms swing out suddenly (Tai Chi)*: the pose model then sees a cropped arm for up to N - 1 frames. Mitigations: the margin; the detector re-run when a person is lost; N is measured in P3.07
   (N = 1, 5, 10, effect on the keypoints). The default 5 is provisional.
2. *A hidden limb gets a low score*: `min_valid_keypoints` = 6 of 26 is lenient on purpose (the box only needs the visible part); if a person is lost too early the detector re-run recovers within the same frame.
3. *The same person can be found twice or a ghost can appear* (detector false positives): not handled here; P3.04 to P3.06 choose and follow one target. Raw means raw.
4. *CUDA is not bit-exact between runs*: tests compare with a tolerance in pixels, measured on the first run and then fixed in the test with the reason written.
5. *Long segments*: 6 minutes at 30 fps = 10 800 frames; the arrays are small (about 2 MB per person), the frames are decoded one at a time. No streaming to disk in this task (P7 decides).
6. *Decode speed of 1080p AV1 or H.264 and the detector at 30 ms* will dominate the real-time factor; measured in P3.07, not optimised here.

## 2. Plan

**Design:** as in section 1. One module, `pose/runner.py`; no change to `rtm.py` or `frames.py`. Reading: `read_manifest(recording_dir / "recording.json", RecordingManifest)`; the table `pts.parquet` with `pyarrow`;
frames with `iter_frames(source, t0, t1, rotation_deg=manifest.display_rotation)`. The frame index is found by matching the decoded `pts` to the table (`np.searchsorted` on the sorted `pts` column, then an equality check), so it is the row of the file and
VFR or an offset start cannot shift it. The first and last rows of the window come from the table (`t_sec` in `[t0, t1]`), and the number of decoded frames must equal the number of those rows.
