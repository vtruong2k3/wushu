## 1. Analysis

**Goal:** a template that a participant (or a guardian) signs before any recording enters the system, with three
separate permissions (analysis, training, sharing), a retention date and a way to withdraw. The agent is not a lawyer:
the legal wording and the review are O's (plan check: "O approves the legal side").

**Facts read from the code and docs (2026-11-15):**

- `participant` table: `consent_ref TEXT NOT NULL`, `consent_analysis` default 1, `consent_train` default 0,
  `consent_share` default 0, `retention_until TEXT`. So analysis is the condition to take part; training and sharing
  are opt-in.
- AGENTS.md §9.5: a recording enters only with a pseudonym and a consent reference; `consent_train = 0` means never used
  for training or model selection; `consent_share = 0` means it never leaves the controlled machine nor is shown to
  other participants; withdrawal or deletion removes the recording and everything derived (task P8.14, which also does
  backup and restore; this file and AGENTS.md first cited P8.12, the report export, see BUG-0044).
- `TECH_WORKFLOW_V1.md` §4.2 example: `consent_ref` like `CONSENT-2026-011`.
- The sync signal is the microphone, so the **voice is recorded** as well as the image: the form must say so.

**In scope (`Docs/consent_form.md`, a template with no personal data):**

1. What is recorded: video of the whole body (the face is visible), audio, and the data derived from them (body
   keypoints, measurements); who sees what (coaches, the engineering team).
2. The purpose and the limits: an internal measurement tool to support coaches; not a score, not a medical use.
3. Three separate tick boxes: analysis (needed to take part), training of models, sharing. Sharing covers both leaving
   the team and being shown to other participants, for example a take used as a reference in a side-by-side comparison
   (P6, P8.13): AGENTS.md §9.5 says that with `consent_share = 0` a recording is never shown to other participants.
4. Retention: a date or an event, filled per participant (`retention_until`).
5. Withdrawal: how to ask, who handles it, what is deleted (the recording and all derived data and reports), how long
   it takes.
6. Minors: guardian consent plus the minor's own agreement; the same three permissions and the same withdrawal.
7. Identification: the pseudonym assigned and the `consent_ref` format `CONSENT-YYYY-NNN`; the register that links a
   real person to a pseudonym is kept outside the repository by O.
8. A mapping table from each tick box and field to the database columns, for P9.01 and T-DATA-02.

**Out of scope:** the legal text itself and the jurisdiction check (O and a legal adviser), the signed originals and the
register (outside git, P9.01), the deletion procedure code (P8.14).

**Constraints that apply:** AGENTS.md §5.9, §9.5; the template in git contains no names, no signatures, no contact data.

## 3. Plan re-read (before writing the template)

- Plan re-read: 2026-11-15 — checked against `migrations/0001_init.sql` (`participant`: `consent_ref` NOT NULL,
  `consent_analysis` default 1, `consent_train` default 0, `consent_share` default 0, `retention_until` nullable text),
  AGENTS.md §9.5, `TECH_WORKFLOW_V1.md` (§4.2 example `CONSENT-2026-011`; §6 lines on `consent_scope` and on deletion),
  the plan rows P8.12, P8.14, P9.01 and the tests T-STORE-07, and the capture protocol (P1.05) for consistency.
- **Findings that change the text (the plan's steps stay):**
  1. The deletion task is **P8.14**, not P8.12 (BUG-0044, fixed here, in AGENTS.md §9.5 and in the P0.06 notes).
  2. What P8.14 deletes, from T-STORE-07 and the TECH_WORKFLOW line on deletion: recording, proxy, audio, every run, clip and
     report of that participant; an `audit_log` entry is written. The plan does **not** say that it also deletes coach
     reviews and segments of the recording, backups, or anything already built from the data (a trained model, a
     reference template). The form must not promise more than P8.14 will do, so it lists exactly the first group and
     leaves the rest as blanks for O ("[O quyết định]"), noted in the mapping part as requirements to settle before P9.01.
  3. The database has no column for "minor / guardian consent" or for the version of the form that was signed, and
     `consent_analysis` may be 0 (the CHECK allows 0 and 1) although analysis is the condition to take part. So: the
     register that O keeps outside git records the form version and the guardian; the recording code (P9.01, P2) must refuse
     a participant with `consent_analysis = 0`. Both are written as notes for P9.01, not as schema changes.
  4. Law (flag only, not interpreted): a web search summary names the Law on Personal Data Protection 91/2025/QH15
     (effective 2026-01-01) and its guiding Decree 356/2025/NĐ-CP, after Decree 13/2023/NĐ-CP. Not checked against the
     official gazette. Whether face, voice and body measurements count as sensitive data, the age of a minor, retention
     and what withdrawal must cover are for O and a legal adviser.
  5. Q1–Q6 have no answer: plan defaults (Vietnamese, legal review by O, paper, retention left blank, the minors procedure
     written anyway, the trial performer signs the same form; P1.09 depends on this task, DEC-0017).
