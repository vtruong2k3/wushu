## 1. Analysis

### 1.1 Goal

Run the whole comparison chain (quality layer → features → cost → DTW) on real recordings with labels, and report two
things the plan asks for (T-CMP-09, acceptance of P6):

1. **Classes:** the distance between two segments of the same technique is smaller than between two techniques, for most
   of the 13 classes of UMONS-TAICHI.
2. **Boundaries:** the boundaries of the labelled parts of a reference sequence, carried to a query sequence of the same
   routine through the warping path, against the query's own labels: temporal IoU and the error in seconds.

The numbers are **out of domain** (13 basic techniques, not the 24-form; a Kinect, not video pose) and are reported apart,
never as the product's accuracy (AGENTS.md §9.4 item 4).

### 1.3 Scope

**In:** the registry note for this use (before any file is read); `bench/umons_compare.py` (IDs of segmented files, the
`.lab` reader, the two experiments, aggregation, tables, CSV); `tools/umons_compare.py` (sub-commands `classes` and
`boundaries`, `--umons ROOT`, `--out`, `--seed`, `--max-pairs`, numbers and IDs only, exit codes 0, 1, 2); tests;
`Docs/reports/p6_umons_check.md`. **Out:** any tuning of the comparison on UMONS (its settings are inputs; a value chosen
here would be learned on out-of-domain data), training, the product's accuracy.

### 1.4 Design

- **Classes:** for each class `G` and side `D`, choose (with the seed) up to `R` reference segments and up to `Q` query
  segments **of other performers** (grouped by performer, AGENTS.md §9.4 item 5: never a performer against themself); align
  every query with every reference of the same side, all classes; report per class the median distance to its own class and
  to the others, whether the own is smaller, the share of classes where it is, and the nearest-class accuracy (1-NN) as a
  second number. Default sample: `R = 3`, `Q = 5` (about 2,500 alignments of about 225 × 225).
- **Boundaries:** pairs of continuous sequences of the same capture code (`Cxx`) from two performers **whose label sequences
  are equal** (the labels in order, rests included; pairs that differ are counted and left out); align the whole sequences;
  carry each labelled part `[t_start, t_end)` of the reference to the query through the matched query time of the path;
  compare with the query's part of the same rank: temporal IoU and the errors of the start and the end in seconds;
  distributions per label family (`ex`, `tech`) and overall.
- **Settings** (`min_visible`, `band`, `step`, weights, and the quality chain's defaults) are arguments of the tool, echoed
  in every output; the report states them; nothing is tuned on these files.

`tests/helpers/umons_fixtures.py`, `P6.03b` §4 and §5, and the folder layout of the dataset, names only). Nothing in the plan
changes a contract; these are choices that the plan left open or facts it had wrong:

1. **The registry note** went into the D12 row of the summary table (line 17 of `DATASET_REGISTRY_TAIJI.md`, where P4.08 and
   P5.08 wrote theirs), not into the D12 section below it. Done first (§4, step 1a).
2. **The reader of the dataset.** `bench.umons.parse_kinect(text, sequence_id)` accepts a sequence id (`P01T01C03`) only, so a
   segmented file is parsed with its *parent* sequence id and keeps its own id (`P01T01C03G05D01S02`) in this module; I do
   not edit `bench/umons.py`. The dataset's three folders hold `License.txt` plus 111 / 1,815 / 131 files
   (`Kinect`, `Segmented_Kinect`, `Labels`).
3. **Seeded choice.** Every "random" choice (the references, the queries, the sampled pairs) orders the candidates by a
   SHA-256 of `seed` and the id, not by a random-number library, so the same seed gives the same choice on every platform
   and version (the report can name its seed and be re-run).
4. **Classes.** The headline table is **per class, pooled over the two sides** (13 rows, the share of classes that the plan
   asks for) with the same table per side as detail; a pair is aligned only inside one side. Own-class and other-class
   medians are over pairs (query, reference) of different performers; a pair with no path (`no_path`: lengths more than
   2:1 for `symmetricP1`) is left out of the medians and **counted per own/other**, so that it cannot hide a bias.
5. **Boundaries.** Parts are the intervals between consecutive `.lab` onsets; `_` (rest) parts count for the equality of the
   label sequences but not for the IoU and the errors; the **last** part of a file has no end (no later onset) and is left
   out and counted. A reference boundary outside the span of the reference's feature clock is left out and counted
   (never clamped). **A baseline is added** (uniform scaling of the clock by the ratio of the two durations, no
   warping) so that the numbers have something to be read against; it needs no data beyond the pair's own times.
6. **Reader rules.** A `.lab` time must be a finite number of 0 or more and **strictly increasing**; a label must be `_` or
   `ex`/`tech` + digits + optional `l`/`r`; any line that is not "time label" is refused with its line number (a file
   that fails is listed by id and makes the exit code 1: it is never skipped silently).
7. **Settings** are arguments with the plan's defaults (Q3): `min_visible` = half of the 21 units rounded up (11),
   `band` 0.2 for `classes` and 0.1 for `boundaries`, `symmetricP1`, weights 1; `min_scale_s` and `min_segment_length` are
   not applied (echoed as `None`). The quality chain runs with `QualityParams()` defaults.
