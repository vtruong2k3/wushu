## 1. Analysis

**Goal:** the fourth step of the quality layer (W6). The Butterworth filter of P4.05 (`filtfilt`, order 4, 6 Hz) needs samples on a
regular clock. A video with a variable frame rate (VFR) has rows at irregular real times (`pts.parquet`, `t_sec`). This task
resamples the gap layer of P4.02 onto a uniform grid **by linear interpolation in real time**, and keeps the map between the grid and
the source rows so that a layer on the grid can be brought back to the source timestamps (W6: "resample linearly to a uniform grid to
filter, then keep both grids; write `resampled = true` in the manifest"). When the timeline is already uniform (every constant-frame-rate
video: all of D20) the stage is the **identity**: the grid *is* the rows, no value is touched, `resampled` is false.

**What is not obvious, and what the analysis measured (numbers only, nothing committed):**

- **The real footage needs no resampling.** The 22 target chunks of the P3.08 pass (four D20 videos, N = 1; 24 fps in three, 30 fps in one;
  86,303 tracked frames in 157,366 rows) have timelines that are straight lines to within **3 x 10^-9 s** (largest deviation of a frame
  time from the least-squares line over all chunks), every interval equals the median (largest interval over the median 1.0000000000136),
  no interval deviates by 1 ms. So on the footage we have, P4.04 is the identity and a test of the non-identity path can only use
  synthetic timelines (SYN-07, jitter, dropped frames) and the F-VID video fixtures (`vfr_video`, `dropped_frame_video`). The
  measurement M-QLT-04 on real motion is therefore a **round trip at every phase** (below), not a count of VFR frames.
- **What resampling costs, on motion with known truth.** Linear interpolation of a smooth movement has an error of at most
  `a x d^2 / 8` over an interval `d` (`a` = largest acceleration). SYN-05 has `a` of about 1,030 px/s^2 on its 30 fps rows (more at its
  ramp corners), so 0.14 px over 33 ms and 1.3 px over a 100 ms interval. A probe (np.interp on SYN-07 rows, onto a grid at the median
  rate and back): the step-down 30 to 10 fps timeline gives **0.000 px** (the 10 fps rows sit exactly on every third grid point); with 30 %
  jitter on the intervals (24 to 126 ms) the round trip has median 0.000 px, p95 0.049 px and **maximum 3.49 px (1.75 % of the torso)**,
  at the 126 ms intervals. So a flat "2 px" is not the right tolerance for T-QLT-07 on jittered timelines: it has to be the analytic bound
  of the intervals involved.
- **A resampled value is not a measurement.** A grid time that is not a source row gets `(1 - w) a + w b` of two usable cells. That is
  allowed by AGENTS.md 5.1 only if it is **flagged** and never crosses a hole: a grid cell next to an unusable cell is NaN (with the
  cause), never filled; a stretch of time with no frame at all (a pause in the timestamps) is not bridged beyond the limit of P4.02.
- **Gaps at the edges on the way back.** To return a filtered grid layer to the source rows, a row between two grid points needs both to
  be finite. A usable row next to a hole has one grid neighbour that lies inside the hole, so on a VFR clip every hole costs up to one
  usable row on each side when the layer is brought back to the source timestamps. The identity (CFR) loses nothing. This is a property of
  the method, reported and not hidden; which lattice the filtered layer is stored on (grid or source) is decided where the stages are wired
  (P4.07, Q5).

**The rules** (every rule has a test sub-ID below):

1. **The timeline decides, not a flag.** The plan of the grid looks at `t_sec` only. Fit the least-squares line `t ~ a + b i` through the
   row times. The timeline is **uniform** if every row time is within `uniform_tol_s` (+1e-9 s) of the line (0.001 s: a constant 30 fps video
   with a time base of 1 ms has rounding of at most 0.5 ms; a dropped frame is 33 ms away). If it is uniform and `grid_hz` is `None`:
   **identity**: `t_grid = t_sec`, `left = i`, `weight = 0`, `step_s = b`; the layer is copied (values, reasons, flags) and nothing is
   mixed. Zero rows and one row are identity (`step_s` NaN); two rows are always on a line.
2. **Otherwise a regular grid** starting at the first row time: `step_s = 1 / grid_hz` if `grid_hz` is given, else the **median interval**
   (the nominal rate of the clip; for the 30 to 10 fps step-down it is 30 fps); `t_grid[k] = t_0 + k x step_s` for `k = 0 .. K`,
   `K = floor((t_last - t_0 + 1e-9) / step_s)`: the grid never goes beyond the last row, so nothing is extrapolated.
3. **Between two rows.** A grid time `g` lies between rows `l` and `l + 1` (`t_l <= g < t_{l+1}`) with `w = (g - t_l) / (t_{l+1} - t_l)`; a
   grid time within 1e-9 s of a row is that row (`w = 0`: a copy). The time is real: no frame rate is assumed.
4. **A stall is not bridged.** If `w > 0` and `t_{l+1} - t_l > max_step_s + 1e-9 s` (0.150 s, the limit of P4.02: a stretch of that length
   without an observed sample is not interpolated), the grid row is a **stall**: every cell is NaN with the reason `no_frame` and not
   `interpolated`. A grid time that is a row inside a stall is still a copy.
5. **A cell between two usable cells** is the linear mix of the two, `a + w (b - a)` (a constant stays exact), computed in float64 and cast
   to the input dtype, x and y apart. Its
   flag `interpolated` is the OR of the two parents' flags (a value built on a bridged value is not observed). Its reason is `ok` if both
   parents are `ok`; if exactly one parent is not `ok` (it is a bridged cell) the reason of that parent; if both are not, the reason of
   the nearer parent (the left one on a tie). So the output keeps the contract of the gap layer: finite and not `ok` means `interpolated`.
6. **A cell next to an unusable cell is NaN, never filled.** Its reason is that of the unusable parent (of the nearer one if both are
   unusable, the left one on a tie); it is not `interpolated`. So a value never crosses a loss of the target (`not_tracked`), a low-confidence
   hole, an outlier or a gap that P4.02 left open.
7. **Copies.** A grid row that is a source row copies value, reason and flag of that row exactly (bit for bit); `mixed` is `w > 0` and not
   a stall.
8. **The way back** (`to_source(values)`): a source row `i` has grid neighbours `back_left` and `back_left + 1` (grid times at or before and
   after `t_i`, `back_weight` of the way; 0 if `t_i` is a grid time within 1e-9 s). It gets the copy or the linear mix of the two grid
   values if both are finite, otherwise NaN. A row after the last grid time (`beyond`, less than one step) is NaN. For the identity it is a
   copy. `to_source` returns values only: the reasons of a layer on the source lattice, and the cells lost at the edges of holes, are
   assigned by the stage that owns that layer (P4.05, P4.07). *Added when the tests were written:* the bare map can give a value to a
   source cell that was a hole (a grid coarser than the rows has grid times on both sides of it that are finite), so `GridLayer`
   remembers `source_usable` and `GridLayer.to_source` gives no value to a source cell that was not usable at the source.

**Constraints that apply** (AGENTS.md 5): 5.1 no fabricated data: a grid value is a flagged linear mix of two usable values and is never
extrapolated, never filled across an unusable cell, never bridged across a stall; a copy keeps its reason and flag; 5.2 real timestamps: the
grid is anchored at the first real row time, the decision "uniform or not" is made from the timestamps with a stated tolerance, and no frame
rate is assumed (`grid_hz` is only an explicit request); 5.3 layers apart: the gap layer is not changed, the grid layer is new and read-only, and
the map back to the source is kept; 5.4 pixels and seconds documented; 5.5 no universal threshold: `grid_hz`, `max_step_s` and `uniform_tol_s`
are data-validity parameters (what counts as a regular clock, how long a stall is) and not thresholds on a movement; they travel with the
result; section 6: type hints, docstrings with units, `QualityError`, no bare `except`.

**Unknowns, risks, questions** (the maintainer is asked; the proposed answer is applied if there is no other):

- **Q1. The grid rate.** W6 says "for example 30 Hz". **Proposed: the median interval of the clip** (the nominal rate, 24 fps stays 24, 60
  fps stays 60), with `grid_hz` as an explicit override. A fixed 30 Hz would down-sample 60 fps phone video by interpolation (no
  anti-alias filter) and up-sample 24 fps lessons (more rows than data); the filter does not care about the rate, only that it is regular and
  known (`step_s`). Alternative: a fixed 30 Hz for every clip, so that every metric sees the same rate.
- **Q2. When is a timeline "already uniform"?** **Proposed: every row time within 1 ms of the least-squares line** (`uniform_tol_s`); then the
  stage is the identity. The measured D20 deviation is 3 x 10^-9 s and a constant frame rate on a 1 ms time base is within 0.5 ms, so 1 ms
  separates rounding from a real VFR (a dropped frame is 33 ms off). The cost: a filter that assumes a regular clock sees a time error of up to 1
  ms, which is at most 0.6 px at the p99 speed of D20 (590 px/s). Alternatives: always resample (every row is then mixed whenever the grid
  and the rows do not coincide, even by 0.1 ms: more smoothing for nothing), or use the ingestion flag `vfr` (a second source of truth, in
  ticks, that this layer does not have).
- **Q3. A pause in the timestamps.** **Proposed: not bridged beyond 0.150 s** (the same limit as P4.02, a parameter `max_step_s`), the grid
  cells in it are NaN with the **new reason `no_frame` (code 6)**. Without the limit a 2 s stall between two observed rows would be filled with
  a straight line (a fabricated movement). Alternative: reuse an existing reason (`not_tracked` would be false, it is not the tracker's loss).
- **Q4. The flags of a grid cell.** **Proposed:** the rules 5 to 7: `interpolated` is inherited (OR), the reason keeps the cause, a row-level
  `mixed` says "this time is not a source row". Whether the coverage of P4.07 counts a mixed cell of two observed parents as observed or as
  derived is decided there; the information is complete. Alternative: a per-cell `resampled` array (26 times bigger, the same information).
- **Q5. The lattice of the filtered layer.** The filter runs on the grid; the metrics and the UI use real timestamps. **Proposed: this task
  provides both directions** (`resample_layer`, `to_source`) and reports the edge loss on the way back (VFR only); **P4.07 decides** whether the
  filtered layer is stored on the grid (no loss, uniform) or on the source rows (the original timestamps, with the loss at hole edges). The
  alternative of deciding now has no data behind it: no real VFR clip exists in the project yet.
- **Risk: the edge loss on the way back.** See above; the measurement counts it (M-QLT-04) and the handover note says it. It is zero for CFR.
- **Risk: a coarse time base drifts against the grid.** For a non-identity timeline the median interval of rounded ticks (33 or 34 ms) can be a
  little off the true mean, so the grid slowly slides against the rows and almost every grid row is `mixed` (still correct and flagged, with
  the interpolation error below). The caller can pass `grid_hz` from the container's rate. No piecewise anchoring is built: VFR is rare (the
  protocol asks for a locked frame rate) and the error is bounded.
- **Risk: smoothing.** Linear interpolation is a low-pass filter; the round trip error is bounded by `a x (d^2 + s^2) / 8` (`d` = the longer
  source interval, `s` = the grid step). M-QLT-04 measures it on the real motion of D20 at every phase.
- **Risk: cost.** The work is gathers by index on `(G, 26, 2)` arrays (about 45 MB of float64 for a one-hour 30 fps clip): no blocks are
  needed; a test checks a long timeline for shape and for agreement with a short run.
- **Risk: the same hole is told twice.** Hampel's time cut (0.25 s) and the stall rule (0.150 s) are different rules for different layers (a window
  of cells, a bridge of values); the plan keeps both limits as separate named parameters and says so in the docstrings.

## 2. Plan

**Design:**

```python
# quality/resample.py
MAX_STEP_S: Final = MAX_GAP_S          # 0.150: not bridged beyond this (same limit as P4.02)
UNIFORM_TOL_S: Final = 0.001           # [s] a timeline within this of a straight line is uniform

@dataclass(frozen=True)
class ResampleParams:
    grid_hz: float | None = None       # > 0 and finite: the grid rate; None = the median interval of the clip
    max_step_s: float = MAX_STEP_S     # > 0, finite
    uniform_tol_s: float = UNIFORM_TOL_S   # >= 0, finite

@dataclass(frozen=True, eq=False)
class GridMap:  # timing only: t_source, t_grid, step_s, left, weight, stall, identity, back_left, back_weight, beyond
    resampled: property
    def to_source(self, values: np.ndarray) -> np.ndarray: ...   # (G, ...) -> (T, ...), NaN where a grid neighbour is NaN

@dataclass(frozen=True, eq=False)
class GridLayer:  # keypoints, reason, interpolated, mixed, gridmap, params; properties usable, observed

def plan_grid(t_sec, params=None) -> GridMap
def resample_layer(keypoints, reason, interpolated, t_sec, params=None) -> GridLayer
def resample_gaps(result: GapResult, t_sec, params=None) -> GridLayer
```

Data flow: `check_gap_layer` (shapes, dtypes, the contract) → `plan_grid` (the line fit, identity or the regular grid, `searchsorted` for `left`
and `weight`, the stall mask, the inverse map) → gather the two parents of every grid row for every joint (`kp[left]`, `kp[left + 1]`, with the
last row guarded) → mix in float64 where both parents are usable and not a stall → reasons and flags by the rules 5 to 7 with boolean masks →
read-only result. `to_source` does the same gather on the grid with `back_left` and `back_weight`. No loops over cells; the slow oracle of the
tests is the loop.
